# 이상상태 시나리오 및 데이터 수집 전략

이 문서는 실제 Jetson Orin Nano 센서 설치 후 어떤 이상상태를 볼 것인지, 그리고 관련 데이터셋이 없는 조건에서 어떤 순서로 모델을 만들 것인지 정리한다.

## 핵심 전제

현재 설치하려는 실제 센서 조합과 설치 환경에 대응되는 학습 데이터셋은 없다.

따라서 첫 단계 목표는 센서만 붙여서 기존 모델을 바로 신뢰하는 것이 아니라, 현장에서 정상 데이터를 안정적으로 쌓고 안전하게 검증 가능한 이벤트를 기록하는 것이다. 현재 ONNX 모델은 Jetson GPU 추론과 전체 파이프라인 검증용 기준 모델로 사용하고, 실제 현장 이상상태 판정 모델은 현장 데이터 수집 이후 재학습한다.

## 2026-07-23 현재 실행 결정

1차 현장 설치에서는 센서를 추가하지 않는다. 기존 ONNX 모델의 입력 구조와 직접 연결되는 아래 4종 센서를 먼저 안정화한다.

- PureThermal Mini Pro + FLIR Lepton 3.5
- NTC 10K 3950 + ADS1115
- Sensirion SPS30
- DHS20P400A-CL420 전류 센서

BME680, SGP30, SCD30은 후보 센서로만 기록하고 1차 설치 범위에서는 제외한다. 이유는 추가 센서가 들어가면 배선, 드라이버, 입력 feature 수, 모델 구조가 모두 바뀌어 현장 데이터 수집 시작이 늦어지기 때문이다.

1차 목표는 기존 4종 센서로 실제 현장 정상 데이터를 모으고, 기존 모델과 정상 기반 anomaly detection의 baseline을 만드는 것이다. 추가 가스/환경 센서는 기존 4종만으로 공기질 이상 구분이 부족하다는 데이터 기반 근거가 생긴 뒤 검토한다.

## 학술적 포지셔닝

이상상태 데이터가 없는 조건에서 정상 데이터만으로 정상 분포를 학습하고, 그 범위를 벗어나는 신호를 이상으로 판단하는 접근은 `novelty detection`, `anomaly detection`, `one-class classification`으로 정리할 수 있다.

다만 논문/보고서 표현은 정확해야 한다.

- 가능: "정상 데이터 기반 이상 징후 탐지"
- 가능: "multi-sensor normality modeling"
- 가능: "현장 이상 데이터 부족 조건에서의 one-class anomaly detection"
- 주의: "유독가스 누출/배전반 화재/열 폭주 3-class 분류"라고 주장하려면 해당 이상상태 라벨 데이터가 필요하다.

초기 모델 출력은 `정상/이상 의심`으로 두고, 이상 원인은 센서 패턴으로 추정한다. 예를 들어 PM/VOC가 먼저 오르면 공기질 이상, 열화상/NTC가 먼저 오르면 과열, 전류와 온도가 함께 오르면 장비 부하 이상으로 해석한다.

학술 평가 지표도 정확도/F1보다 아래 항목이 먼저다.

- 정상 구간 false alarm rate
- 장비별 정상 범위 안정성
- sensor drift와 계절/환기 변화에 대한 robustness
- controlled event에서 time-to-detect
- 센서 ablation을 통한 기여도
- 현장 라벨이 누적된 뒤 supervised 모델 대비 성능

## 설치 환경 정의

대상 환경은 작업자가 함부로 접근하면 안 되는 공장 설비 구역이다. 예시는 그라인더, 모터, 배전반, 회전체 장비 주변이다.

목표는 설비 주변의 위험 징후를 조기에 감지해서 작업자 접근 제한, 관리자 알림, 설비 점검 판단을 돕는 것이다.

## 목표 클래스

| 클래스 | 상태 | 의미 |
| --- | --- | --- |
| 0 | Normal | 정상 운전, 정지, 대기, 환기 변화 등 위험으로 보지 않는 상태 |
| 1 | Gas / Air-quality anomaly | 유독가스 누출 또는 공기질 급변 의심 상태 |
| 2 | Electrical panel fire | 배전반 화재, 훈소, 연기, 국소 과열 의심 상태 |
| 3 | Motor / equipment thermal runaway | 모터 또는 장비의 열 폭주, 과부하, 냉각 불량 의심 상태 |

주의: BME680, SGP30, SCD30만으로 특정 유독가스 종류를 식별할 수 없다. CO, H2S, NH3, 용제 증기처럼 목표 가스가 정해지면 그 가스 전용 센서를 추가해야 한다. 현재 후보 센서는 생명안전용 단독 경보기라기보다 조기 징후와 보조 판단용으로 본다.

## 데이터 수집 단계

### 1단계: 센서 bring-up

각 센서가 Jetson에서 안정적으로 읽히는지 먼저 확인한다.

- I2C 주소 충돌 확인
- 샘플링 주기 확인
- 단위와 범위 기록
- 센서 disconnect, timeout, checksum 오류 처리
- CSV/JSON 로그 저장 확인

### 2단계: 정상 기준 데이터 수집

관련 데이터셋이 없기 때문에 정상 데이터가 가장 먼저 필요하다.

- 장비별 최소 며칠 이상 수집
- 정지, 대기, 저부하, 고부하, 청소, 환기 변화 같은 정상 운전 조건을 구분 기록
- 시간대, 작업 종류, 설비 ID, 위치, 주변 온습도 메모
- 센서 위치를 바꾸면 다른 데이터셋으로 취급

### 3단계: 안전한 검증 이벤트 기록

실제 유독가스 누출이나 화재를 만들면 안 된다. 검증 이벤트는 안전 승인된 방식으로만 진행한다.

- 열 검증: 손난로, 온수병, 히터 테스트 장비 등 통제 가능한 열원
- CO2 검증: 사람 호흡, 환기 변화 등 낮은 위험의 변화
- 전류 검증: 실제 장비 부하 변화 또는 더미 부하
- 미세먼지/연기 검증: 현장 안전 기준을 만족하는 테스트 장비 또는 승인된 테스트만 사용

이 단계의 목적은 센서 반응과 시간 동기화를 확인하는 것이며, 학습용 이상 데이터라고 바로 단정하지 않는다.

### 4단계: 라벨링

모델 학습에는 센서값보다 라벨 품질이 더 중요하다.

최소 라벨 필드:

```text
timestamp_start
timestamp_end
site_id
equipment_id
sensor_position
class_id
event_name
operator_note
confidence
```

라벨은 `Normal`, `Gas/Air-quality`, `Electrical panel fire`, `Thermal runaway` 중 하나로 시작하되, 초기에는 `unknown`, `maintenance`, `sensor_error`도 허용한다.

## 초기 모델 전략

데이터셋이 없는 상태에서 바로 4-class supervised classifier를 신뢰하면 안 된다. 시작 전략은 아래 순서가 맞다.

1. Rule-based alarm

센서별 임계값, 변화율, 지속시간, hysteresis를 사용한다. 예를 들어 온도 절대값보다 `최근 5분 상승률`, `열화상 핫스팟 면적`, `PM2.5 급증`, `전류 급증` 같은 feature를 본다.

2. Normal-only anomaly detection

정상 데이터만 충분히 모은 뒤 장비별 정상 범위를 만든다. 이동 평균, z-score, EWMA, Isolation Forest, autoencoder, forecasting residual 같은 방식이 후보가 된다.

3. Weak label / event label 학습

정비 기록, 작업자 메모, 안전 검증 이벤트를 라벨로 붙여서 초기 분류 모델을 만든다. 이 단계에서 클래스 불균형과 라벨 신뢰도를 반드시 기록한다.

4. Supervised 4-class model

라벨링된 현장 데이터가 충분히 쌓인 뒤 센서 feature vector를 확정하고 모델을 재학습한다. 이후 ONNX로 export해서 Jetson에서 다시 검증한다.

## 현재 ONNX 모델의 위치

현재 모델 입력 센서 채널은 아래 기준이다.

```text
[NTC, PM1.0, PM2.5, PM10, CT1, CT2, CT3, CT4] + thermal image
```

BME680, SGP30, SCD30을 추가하면 입력 feature가 달라진다. 이 경우 기존 ONNX 모델을 그대로 사용하면 새 센서 정보는 반영되지 않는다.

현 단계에서 기존 ONNX 모델은 다음 용도로 사용한다.

- Jetson GPU/ONNX Runtime/TensorRT 검증
- 실시간 window 처리 구조 검증
- thermal + 8채널 입력 파이프라인 기준점
- 현장 데이터가 쌓인 뒤 새 모델과 비교할 baseline

## 우선 구현 순서

1. SPS30, PureThermal, NTC/ADS1115를 안정적으로 읽는다.
2. 24V 전원과 shunt resistor가 준비되면 DHS20P400A-CL420 전류 센서를 읽는다.
3. 모든 센서값을 같은 timestamp 기준으로 저장하는 통합 logger를 만든다.
4. 정상 운전 데이터를 먼저 수집한다.
5. rule-based alarm을 붙여 현장 피드백을 받는다.
6. 데이터가 쌓이면 현장용 feature와 라벨 체계를 확정한다.
7. 새 모델을 학습하고 ONNX/TensorRT로 Jetson에 배포한다.
8. 필요성이 확인되면 BME680, SGP30, SCD30, 진동 센서 등을 2차로 추가한다.

## NTC와 BME680 온도 채널 판단

BME680은 온도 값을 제공하지만, 장비 표면 온도를 직접 재는 센서로 쓰기에는 적합하지 않다. BME680의 온도는 센서 내부/PCB/주변 공기의 영향을 받으며, gas heater 동작과 보드 배치에 따라 실제 주변 온도보다 높게 나올 수 있다.

따라서 현재 판단은 아래와 같다.

| 목적 | 권장 센서 | 이유 |
| --- | --- | --- |
| 모터 하우징, 배전반 외함, 케이블 덕트 등 표면 온도 추세 | NTC 10K 3950 | 부착 위치의 접촉 온도를 직접 측정한다. 열 폭주/국소 과열 감지에 유리하다. |
| 센서 박스 주변 환경 온도/습도 보정 | BME680 | 공기질 센서 보정과 주변 환경 기록에 유리하다. |
| 국소 핫스팟 위치 확인 | PureThermal | 면 단위 온도 분포를 본다. |

데이터 크기 측면에서 BME680과 NTC는 모두 거의 부담이 없다. 실제 저장 공간은 열화상 raw frame이 대부분 차지한다. 따라서 센서 선택 기준은 데이터 크기가 아니라 측정 위치, 반응 속도, 해석 가능성이다.

결론: BME680으로 NTC를 대체하지 않는다. 1차 설치에서는 NTC를 그대로 유지하고 BME680은 추가하지 않는다. BME680은 나중에 주변 환경 보정이나 VOC 계열 정보가 필요하다는 근거가 생겼을 때 2차로 추가한다.
