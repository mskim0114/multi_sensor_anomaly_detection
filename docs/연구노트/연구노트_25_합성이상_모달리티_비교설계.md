## 3. 비교 질문과 모델

### 3.1 사전 질문

- **Q-M:** 같은 주입기·분할·seed·임계값 규칙에서 융합이 각 단독 모달리티보다 실제 클래스별 recall을 높이는가.
  FPR이 함께 커지면 무조건적인 우위로 해석하지 않는다. 두 단독 모델과 각각 비교하고 사후 최고 모델만 고르지 않는다.
- **Q-G:** 정상/합성 이진 분류가 재구성 기반 탐지보다 합성 평가에서 더 좋지만 실제 평가에서는 더 크게 무너지는가.
  `gap_binary − gap_AE`의 부호와 크기를 보고한다. 결과가 반대면 그대로 기록한다.
- **Q-C:** `SYN`이 `NQ`보다 유용한가. 동일 checkpoint를 두 임계값으로 평가해 학습 효과와 보정 효과를 분리한다.
  이 규약에서 `tau_SYN ≥ tau_NQ`이므로 recall 개선을 기대하는 비교가 아니다. FPR 감소와 recall 유지/손실을 함께 측정한다(§7).
- **Q-O:** blind–oracle 차이가 큰가. 주입 가정의 병목을 보는 질문이며 oracle 우위를 전제하지 않는다.

위 Q는 이 계획 내부 식별자다. 논문의 기존 H1/H2/H3나 현장 FIELD-HA~HC를 재정의하지 않는다.

### 3.2 기본 6개 조합

| 입력 | 정상 재구성 탐지 `AE` | 정상/합성 이진 분류 `BIN` | 보는 정보 |
|---|---|---|---|
| `S` 센서 단독 | S-AE | S-BIN | NTC, PM1.0, PM2.5, PM10, **AI Hub CT1** |
| `T` 열화상 단독 | T-AE | T-BIN | 방사온도 30×120×160, 색상 표시 이미지 아님 |
| `F` 학습된 융합 | F-AE | F-BIN | 위 S와 T의 동일 시간창 |

CT1은 주 비교의 고정 기준이며 **AI Hub CT1이 현장 CT 설치점과 같다는 가정은 하지 않는다.**
CT2를 선택한 S/F는 사전 지정 민감도 분석이다. #23의 결과를 이미 보고 선택했다는 사실도 기록한다.
T는 CT 선택과 무관하므로 재학습하지 않는다. 8채널은 필요할 때만 별도 AI Hub 진단 대조군으로 둔다.

### 3.3 구조와 학습 조건

1. 센서 인코더는 V2+의 다중 차분 `[1,5,10]` + 3층 LSTM(hidden 128) + projection/SE 구조를 출발점으로 삼는다.
   SE를 비교 변수로 추가하지 않는다. 정상-only 실험에 기존 SupCon 4-class 목적을 복사하지 않는다.
2. 열화상은 V2+의 frame CNN(16/32/64, 3회 pooling)과 frame projection 128을 재사용한다.
   원 `V2Plus.encode`는 시간 평균으로 열화상 순서를 잃으므로, 이 계획에서는 **공통 3층 LSTM 128**으로 시간축을 집계한다.
   T/F 모두 동일하게 적용한다. 이 추가 구조는 미검증 후보이며 기존 V2+와 같은 모델이라고 부르지 않는다.
3. 각 단독 모델은 128차원 bottleneck, F는 두 128차원 출력을 concat한 뒤 128차원으로 projection한다.
   S/T와 F의 대응 branch 초기 가중치는 같은 seed에서 명시적으로 복사한다. RNG 호출 순서만으로 동일성을 가정하지 않는다.
4. AE는 bottleneck과 창 내 위치를 이용하는 sequence decoder로 입력을 복원한다.
   센서는 30×5, 열화상은 30×120×160을 출력한다. 원 입력을 decoder에 우회 전달하는 skip/teacher forcing은 사용하지 않는다.
   시간 평균 임베딩을 원 시퀀스라고 간주하지 않는다. T/F의 열화상 decoder 구조는 동일하게 유지한다.
5. AE loss는 센서/열화상 각각 **원소 평균 MSE**; F는 `0.5*MSE_S + 0.5*MSE_T`다.
   픽셀 수 때문에 열화상이 loss를 지배하지 않도록 합계 MSE를 사용하지 않는다. residual score도 같은 식을 사용한다.
6. BIN은 같은 인코더·bottleneck에 1-logit head를 붙여 BCE로 학습한다. 배치의 정상:합성 비율은 1:1,
   추가 class weight/sampler 이중 보정은 없다. 합성은 원문 §5에 따라 BIN 학습에도 사용된다. 따라서 BIN을 “정상만 학습”으로 표기하지 않는다.
7. 공통 예산은 30 epoch, AdamW(lr 1e-3, weight_decay 0.01), fixed cosine LR, FP32, effective batch 16,
   seed `[42,123,456]`, 결정론 모드다. 이 값은 **초기안**이다. 본 평가 전 dev만으로 변경하면 모든 비교군에 같은 규약을 적용하고 계획 버전을 올린다.
8. 30 epoch를 모두 수행하고 AE는 dev-Normal loss, BIN은 dev-Normal/합성 BCE가 최소인 checkpoint를 선택한다.
   동률이면 이른 epoch. held-out 라벨을 보면서 학습률·epoch·구조를 변경하지 않는다.

같은 branch·bottleneck을 쓰더라도 F의 파라미터와 연산량은 더 크다. 파라미터 수·peak memory·실측 학습시간을 함께 보고하고,
융합 이득을 **용량과 분리된 인과 효과**라고 부르지 않는다. 순수 용량 효과는 후속 capacity-matched 비교의 질문이다.

**추가 학습 없는 대조군 `L`:** S-AE와 T-AE 점수를 각각 dev-Normal의 장비 균등 가중 ECDF로 변환하고 `0.5*u_S+0.5*u_T`로 결합한다.
cal에서 NQ/SYN 임계값을 별도로 정한다. 학습된 F가 단순 점수 결합 L보다 나은지도 볼 수 있다.
L은 두 모델을 실행하므로 추론 비용을 따로 합산/실측한다. 이는 네 번째 기본 학습 모델이 아니다.

### 3.4 P0에 추가하는 통계 기준 모델

신경망의 비용을 해석할 기준으로 **B-NTC/B-MD/B-THERM/B-LATE**를 미리 고정한다.
SGD 학습은 없지만 fit-Normal 통계와 B-LATE의 dev-Normal ECDF를 추정하므로
“데이터 적합이 전혀 없는 규칙”이라고 부르지 않는다. 네 기준 모델은 §4의 동일 split·pure-Normal·품질 적격 창을 사용한다.

| ID | 점수와 적합 정보 | 임계값·평가 |
|---|---|---|
| B-NTC | run-local fit-Normal mean/std로 만든 NTC z-score의 창 내 절댓값 최댓값 | 동일 cal의 NQ/SYN, 동결 후 동일 held-out 창 |
| B-MD | 정규화된 5채널 각각의 시간 평균·표준편차(ddof=0)·절댓값 최댓값, 총 15특징의 squared Mahalanobis 거리 | B-NTC와 동일; thermal 입력은 사용하지 않음 |
| B-THERM | T-AE와 동일한 fit-Normal global mean/std로 만든 온도 z-score의 시간·픽셀 전체 절댓값 최댓값 | 동일 cal NQ/SYN; 센서 입력은 사용하지 않음 |
| B-LATE | B-MD/B-THERM 점수의 dev-Normal ECDF 등가중 결합 | dev는 스케일 적합, cal은 NQ/SYN 임계값 적합으로 분리 |

B-MD는 fit의 pure-Normal 창에서 **장비별 총 가중치를 같게** 하여 특징 mean/std와 공분산 `C`를 적합한다.
특징을 표준화한 뒤 `C_reg = 0.9*C + 0.1*trace(C)/15*I + 1e-6*I`로 고정한다.
마지막 항은 무차원 특징 공분산의 수치 안정화이며 원시 센서 보정이 아니다. 0-분산 특징은
constant로 기록하고 scale=1을 사용한다. score는 `(z-mu)^T C_reg^-1 (z-mu)`이며 선형계 풀이로 계산한다.
계수·특징·score 방향을 held-out 성능으로 고르지 않는다. 모든 적합 ID·통계·regularization 값을 저장한다.

**B-LATE:** `0.5*ECDF_dev_MD(score_MD) + 0.5*ECDF_dev_THERM(score_THERM)`이다.
각 ECDF는 dev 장비별 총 가중치가 같은 `sum(w_i * I(dev_score_i <= score))`로 정의한다.
적격 장비 수 D, 장비 d의 적격 창 수 n_d에 대해 `w_i=1/(D*n_d)`로 두어 전체 가중치 합을 1로 맞춘다.
dev 범위 밖은 0/1로 포화하고 외삽하지 않는다. 동일한 규칙을 §3.3의 neural 점수 결합 L에도 적용한다.
ECDF 포화율과 퇴화 임계값을 보고하며, cal·held-out 점수로 ECDF나 가중치를 다시 적합하지 않는다.

4기준 모델×4fold = **통계 기준 모델 구성 16건**이다. fit 통계를 쓰는 단독 기준 모델 12건과
dev ECDF 결합 구성 4건을 뜻하며, 독립 학습 16회라는 뜻은 아니다. 공유 normalizer/점수를 재사용한다.
neural 108회에는 포함하지 않는다. 같은 fold의 파라미터·ECDF는 seed/arm에 재사용하고,
합성 bank와 NQ/SYN 비교는 해당 신경망 비교군의 동일 bank·가중치를 따른다.
NTC가 4-class 라벨과 높은 상관비를 보였다는 과거 결과는 기준 모델을 둘 이유이며,
정상-only 탐지 성능이나 신경망의 불필요를 입증한 결과가 아니다.

기존 Q-M의 F−S/F−T 직접 비교는 유지한다. 추가로 S는 B-NTC/B-MD, T는 B-THERM, F는 B-LATE와
비교하고 B-LATE−B-MD/B-THERM도 함께 보고한다. F가 센서 기준 모델을 이긴 것만으로 복잡한
융합의 이득을 단정하지 않는다. 이 대조군도 신경망의 용량 효과를 완전히 분리하는 인과 실험은 아니다.
과거 4-class V2+의 모달리티 ablation 수치를 새 정상-only 모델의 기대 성능으로 환산하지 않는다.

**P0에서는 fit/dev/cal의 허용 통계와 정상/합성 경로만 점검한다.** 기준 모델의 held-out 실제 성능도
전체 프로토콜 동결 후 신경망 결과와 함께 공개한다. 그 성능을 먼저 보고 108회 계획을 줄이거나
설계를 바꾸지 않는다. 예산 확대 여부는 §9의 비용·구현 가능성으로 판단한다.

## 4. 데이터 분할과 정보 접근

### 4.1 바깥 4-fold, 안쪽 16/4/4

AI Hub Training 32대에 `src/train_kfold.py:assign_folds(device_ids,4)`를 적용한다.
AGV/OHT를 각각 정렬한 뒤 `i % 4`로 나누는 현재 함수를 보존한다.

| 역할 | 장비 수 | 허용 정보·사용처 |
|---|---:|---|
| `fit` | 16 (AGV 8 + OHT 8) | pure-Normal로 정규화·AE 학습; BIN에는 여기서 만든 합성 추가 |
| `dev` | 4 (2+2) | Normal 및 동결 주입기가 만든 합성으로 checkpoint 선택; AE/late fusion 점수 스케일 |
| `cal` | 4 (2+2) | Normal 및 별도 seed의 합성으로 임계값만 결정 |
| `heldout` | 8 (4+4) | 모든 설정 동결 후 실제 4-class 평가; 동결 주입기의 합성 평가도 별도로 수행 |
| provider Validation | 4 | 전체 프로토콜 동결 후 보고용. 튜닝·모델 선택에서 제외 |

fold `f`의 held-out은 기존 fold `f`다. 다음 fold `(f+1)%4`의 각 기종 4대를 ID 정렬하고
인덱스 0·2를 dev, 1·3을 cal로 배정한다. 나머지 두 fold 16대가 fit이다. 이 규칙은 라벨·성능을 보지 않는다.
따라서 원문의 “24대 Normal 전부 학습”과 학습량이 다르며, 기존 24대 학습 수치와 직접 효과 차이를 계산하지 않는다.
24대 전부 학습하는 재적합은 독립 calibration 데이터가 마련된 후의 별도 연구다.

### 4.2 창·라벨·정규화

- 창 길이 30 tick, stride 10, 1 Hz: 30표본의 첫–끝 timestamp 차이는 29초다. 겹치는 창 수×30을 고유 관측시간으로 환산하지 않는다.
- `pure-normal = all(tick_label == Normal)`을 **창 내부 30 tick에서 검사**한다. 다수결 Normal은 학습 base가 아니다.
  현재 4-class 최빈값 규칙과 Normal=0 동률 우선이면 `[8,6,8,8]`도 Normal이다.
  이때 비-Normal은 22/30이며 이것이 이 규칙의 수학적 최대다. 실제 오염률로 측정한 값은 아니다.
- 주 평가는 30 tick의 class가 같은 창으로 클래스별 recall과 pure-Normal FPR을 계산한다.
  class가 섞인 창은 버리지 않고 별도 majority-label 표에 전부 보고한다. mixed Normal 창 비율을 진짜 정상 FPR에 합치지 않는다.
- 장비 역할을 먼저 정한 뒤 창을 만든다. 세션을 가로지르지 않으며 base의 모든 합성 파생본은 base와 같은 역할에만 존재한다.
- 센서 mean/std와 열화상 global mean/std는 fit의 pure-Normal 창이 참조하는 **중복 제거 raw tick**에서 산출한다.
  기존 `DataConfig` 상수·캐시·checkpoint는 변경하지 않고 run-local normalizer와 해시를 저장한다.
- 변동이 0인 채널은 표준편차 임의 추정 대신 constant-channel로 기록하고 분모 fallback 1 physical unit을 명시한다.
  blind 상대 주입 스케일을 만들 수 없는 채널은 해당 family를 생성 불가로 기록한다. 양의 최소 std를 임의로 지어내지 않는다.
- 주입은 °C/A/µg/m³의 raw 사본에 수행한 뒤 run-local normalizer를 적용한다. per-image min–max로 온도 상승을 지우지 않는다.
- finite/shape/timestamp 검사는 공통으로 적용한다. 세 모델은 동일한 품질 적격 base 창을 평가한다.
  기존 범위 밖 열화상이나 음수 의심값은 별도 QC 목록에 보존하고 자동 clipping/수정하지 않는다.
  그 경고의 합성 base 사용 여부는 아래 §4.2.1에 고정한다.

fit/dev/cal에 기종별 Normal 장비/세션 수가 부족하면 임의로 held-out을 빌려 오지 않는다.
각 partition의 장비·세션·고유 tick·pure/mixed 창·class별 개수를 먼저 출력하고 계획 개정을 기록한다.

### 4.2.1 열화상 QC 경고와 합성 base 자격

**hard-invalid와 soft-QC를 구분한다.** 비유한 값·shape 오류·timestamp 위반은 hard-invalid로
장비/역할/이유별 제외 건수를 기록하고, 모든 모달리티에서 동일 raw base를 제외한다.
hard-valid인 창에 열화상 경고만 있으면 **포함하되 분리 집계**한다. 이 규칙은
fit/dev/cal/held-out/provider Validation과 실제·합성 양쪽에 동일하게 적용한다.

- `thermal_negative_C`: raw 창에 0 °C 미만 픽셀이 하나라도 있음.
- `thermal_outside_legacy_range`: raw 창에 기존 `ThermalStats`의 [30.98,146.10] °C 밖 픽셀이 있음.
  이는 과거 정규화 범위와의 차이를 나타내는 **진단 flag**다. 센서 정격/물리 유효 범위가 아니며,
  음수 섭씨라는 사실만으로 물리적으로 불가능한 측정이라고 단정하지 않는다.
- 두 flag는 사전 고정한 보고용 규칙이며 **표본 선별·normalizer 적합 표본·loss weight·threshold 선택**에
  사용하지 않는다. 과거 전체 Training 통계를 새 blind 적합 경로에 도입하는 규칙이 아니다.

합성 base는 **공통 hard-valid + pure-Normal**이면 적격이다. soft-QC 창도 포함하여 정상/합성 쌍을
유지한다. 주입 전 flag를 모든 파생본에 그대로 상속하고, 주입 후 온도 범위 변화는 별도 필드에 남긴다.
flag를 모형 입력에 넣거나, 주입으로 flag가 생겼다는 이유로 합성을 골라 삭제하지 않는다.
§5.2의 센서 제약·주입 rejection은 별도 검사이며 원본 위반/주입 위반을 계속 구분한다.

장비·역할·class·base QC별 창 수/고유 tick 수와 합성 accepted/rejected 수를 기록한다.
주 표는 전체 hard-valid 코호트이며, **동일 모델·동일 동결 threshold**로 soft-QC 없음/있음의
실제 recall·Normal FPR·합성 TPR·gap과 분모를 별도 제시한다. flag별 threshold 재적합은 하지 않는다.
한 층의 적격 장비/class가 없으면 NA다. 두 flag의 교집합을 기록하고 하나의 창을 두 코호트에 중복 합산하지 않는다.
경고 창이 정상 통계나 점수를 지배할 가능성은 남아 있으므로 이 분리 결과 없이 현장 일반화를 주장하지 않는다.
공급자 명세로 추가 hard-invalid 범위를 확정할 필요가 생기면 평가 공개 전에 별도 프로토콜 개정과 제외 회계를 남긴다.

### 4.3 blind와 oracle의 정확한 의미

- **blind:** 이번 실행의 실제 이상 샘플/통계에 접근하지 않고 공학적 후보와 fit-Normal 통계만으로 주입기를 고정한다.
  원문 §4.2의 32대 8,000 tick std는 Normal-only 및 held-out 제외가 증명되지 않아 사용하지 않는다.
- **oracle:** fit 16대의 실제 이상에만 주입 파라미터를 적합한다. 원 이상은 학습 배치·dev/cal·threshold 함수에 전달하지 않는다.
  oracle 파라미터를 통해 정보가 간접 유입되는 조건임을 명시한다. 실제 이상을 전혀 모르는 조건으로 보고하지 않는다.
- 기존 연구에서 32대와 provider 4대의 결과를 이미 확인했다. 이 실험은 **동결 후 평가 라벨을 차단하는 절차적 blind**이지,
  연구자가 이 데이터의 이상 양상을 처음 보는 완전한 blind가 아니다. provider 4대도 역사적으로 untouched test가 아니다.
- blind 설정·주입 manifest·평가 계약을 먼저 저장한다. oracle을 본 뒤 blind 파라미터를 변경한 결과는 새로운 탐색 실험 ID로 분리한다.
- `fit_detector(normal, synthetic_optional)` / `fit_threshold(normal_scores, synthetic_scores, policy)`에 real severity를 받는 인자를 두지 않는다.
  `evaluate_frozen`만 실제 severity를 읽는다. `fit_oracle_generator`는 분리된 경로로 fit 장비 목록을 강제한다.

## 5. 합성 주입 계약

### 5.1 모든 모델에 동일한 사건을 제시한다

먼저 센서 8채널+열화상 raw 쌍에서 master event manifest를 만들고, S/T/F에 필요한 입력만 projection한다.
baseline 채널 선택은 CT1, 민감도 분석은 CT2에 같은 종류·상대 강도·시점 규칙을 적용하되 채널별 물리 크기는 기록한다.

| family | 센서 변화 | 열화상 변화 | 용도 |
|---|---|---|---|
| sensor-only | ramp/step/spike/variance/drift 중 균등 배정 | 없음 | 센서만 볼 수 있는 변화 |
| thermal-only | 없음 | thermal_blob | 열화상만 볼 수 있는 변화 |
| coupled | NTC/CT 등 사전 지정 결합 | 지연된 thermal_blob | 모달리티 관계가 있는 변화 |

family 가중치는 각 1/3, 강도 가중치도 각 1/3으로 고정한다. 합성 전체 평균 외에 family×강도별 표를 필수로 낸다.
S에게 보이지 않는 thermal-only 변화, T에게 보이지 않는 sensor-only 변화가 있다. 같은 base 입력에 다른 사건 라벨이
붙는 BIN 예도 그대로 기록한다. 이 정보 한계를 학습 실패로만 해석하거나 각 모델에 유리한 사건만 골라 평균내지 않는다.

### 5.2 blind 초기 grid — 물리 검증된 이상 크기가 아님

| 항목 | 사전 후보 |
|---|---|
| 크기 | fit-Normal std의 1/2/4배; 각각을 L/M/H로 부르되 실제 Mild/Moderate/Severe로 이름 붙이지 않음 |
| 시작 | 0~29 tick 중 유효 구간에서 균등; 길이가 창 밖으로 나가는 조합은 제외 |
| 지속 | step/ramp/blob 5/10/20 tick, spike 1/2/3 tick, drift는 30 tick 전체 |
| variance | 평균 0 perturbation을 더해 추가 std가 1/2/4배가 되게 함; realized mean/std 함께 기록 |
| 열점 | 중심이 영상 안에 있는 Gaussian, 공간 sigma 3/6/12 pixel; 시간 진폭 envelope 별도 저장 |
| 모달리티 지연 | 0/2/5 tick; CT 선행·열화상 후행을 후보로 두되 실제 원인 지연이라고 주장하지 않음 |

PM은 합성 결과에서 `0 ≤ PM1 ≤ PM2.5 ≤ PM10`, 전류 크기는 비음수라는 기본 제약을 점검한다.
조건을 깨는 합성은 보정해서 통과시키지 않고 rejected로 기록한다. raw 자체의 위반과 주입이 만든 위반을 구분한다.
정격/측정 상한은 해당 AI Hub 채널의 명세가 확인된 경우에만 적용한다. Jetson CT 정격을 AI Hub CT의 상한으로 전용하지 않는다.
열화상은 legacy min/max에 자동 clipping하지 않는다. 잘린 열점·경계 접촉·실제 Δ°C·최대값을 기록한다.

각 base마다 family×강도 9개 사건을 고정 seed로 배정한다. 파라미터 RNG는 `(protocol, fold, role,
base_window_id, event_id, generator_seed)`로 고정하고, `fit/dev/cal/heldout-eval` seed namespace를 분리한다.
BIN fit은 각 epoch에서 base당 정상 1개와 합성 1개를 균등 순환해 정상 노출 횟수를 통제한다.
dev/cal/eval은 사전 생성된 9개 사건 bank를 그대로 사용한다. rejected/no-op 비율과 유효 bank 크기를 기록하고
실제로 변한 visible feature가 없는 projection도 삭제하지 않는다. 유효 사건 부족은 구현 완료 gate 실패로 보고한다.

### 5.3 원문을 보존하는 확장

창 안에서 끝나는 사건이 주 비교다. **세션 단위 주입 후 창으로 자르기**는 별도 stress 결과로 보고하며
주입 사건 ID를 창과 함께 보존한다. 무작위 timestamp permutation으로 모달리티 정합을 깨는 실험,
미관측 주입 family를 남겨 둔 실험, normal load change를 이상으로 오인하는 사례도 후속 진단이다.
FFC/stale/dropout은 process anomaly와 별도인 관측 품질 문제다. 오프라인 invalidity stress에서는 검출을 강요하지 않고
판단 보류율·유효 coverage를 측정한다. 현장 프로토콜의 stale 보간 금지와 500 ms 규칙을 바꾸지 않는다.

## 6. oracle 적합 범위

oracle은 새로운 생성 모델을 크게 학습하는 단계가 아니다. 같은 함수족을 사용하고 fit 장비에서만
class별 변화량·기울기·기간·센서 동시변화·열점 통계를 추정해 grid/분포를 정한다.
관측되지 않는 물리 대응이나 onset을 만들어내지 않는다. 대응이 불가능한 파라미터는 `not_identified`로 둔다.
주입기 적합 규칙은 blind 결과를 보기 전에 코드와 manifest로 고정한다.

AE의 학습·checkpoint·normalizer는 blind/oracle에 공통이다. 따라서 **동일 AE에 대한 NQ 임계값과 실제 평가값은 두 팔에서 같아야 한다.**
차이가 나면 정보 유입 또는 구현 문제다. BIN은 각 팔의 합성으로 따로 학습하므로 가중치부터 달라진다.
oracle의 이득은 실제 이상 분포를 알고 합성을 개선했을 때의 진단값이며, 현장 기대치가 아니다.

## 7. 두 임계값을 같은 checkpoint에 적용한다

score가 클수록 이상, 판정은 `score > tau`. calibration Normal은 장비별 가중치 합을 같게 한다.
Normal만으로 구성한 cal에서 목표 **window FPR alpha=0.01**을 사용한다. 장비 이동·겹친 창 때문에 현장 1% 보장은 아니다.

- **NQ:** cal-Normal 점수의 장비 균등 가중 empirical 0.99 분위수. 경계 동률을 보수적으로 처리하고 실제 calibration FPR을 저장한다.
  이 조건에는 합성 정보가 들어가지 않는다.
- **SYN:** 동일 cal-Normal과 cal 합성에서 `0.5*FPR_N(tau) + 0.5*(1-TPR_syn(tau))`를 최소화하되
  `FPR_N(tau) ≤ 0.01`인 후보만 허용한다. 합성 가중치는 장비·family·강도 각각 균등이다.
  점수 경계 사이 후보와 항상-normal 후보를 포함한다. 동률은 낮은 FPR, 그다음 높은 tau로 결정한다.

NQ/SYN이 같아지는 결과도 유효하다. 합성의 효용을 보이려고 목적함수·alpha를 사후 변경하지 않는다.
같은 Normal 점수·가중치·alpha에서 NQ는 FPR 제약을 만족하는 최소 임계값이고 SYN도 같은 제약을
따르므로 **`tau_SYN ≥ tau_NQ`**다. 따라서 동일 checkpoint의 어느 평가집합에서든 SYN의 양성 예측은
NQ의 부분집합이며 **recall_SYN ≤ recall_NQ, FPR_SYN ≤ FPR_NQ**다. 이는 실측 결과가 아니라
현재 보정 정의의 수학적 성질이다. Q-C는 더 낮은 FPR을 위해 recall을 얼마나 유지/희생하는지 묻는다.
항상-normal 해가 선택되면 실패를 숨기지 않고 `degenerate_threshold`로 기록한다.
`alpha=0.005/0.02`는 임계값 민감도 표에만 추가하며 그중 좋은 값을 최종 수치로 고르지 않는다.
작은 calibration 표본에서 1% 꼬리값은 불안정하다. 고유 tick/장비/세션 수와 threshold 민감도를 함께 보고한다.

### 7.1 calibration 임계값의 불확실성

stride 10의 창은 인접 창과 20 tick을 공유한다. 그러나 `창 수/3`은 **유효 표본 수가 아니다**.
비중첩 창도 같은 장비·세션의 자기상관을 가질 수 있다. 각 fold의 cal 4대(기종별 2대)라는
독립 장비 수 제약을 명시하고 다음 산출물을 모든 기준 모델·탐지기에 적용한다.

1. 장비·세션·연속 pure-Normal 구간별 창 수, 고유 raw tick 수, 비중첩 창 수, 꼬리 점수/동률 수,
   점수의 lag별 자기상관을 기록한다. 근거 없이 유효 표본 수를 숫자로 환산하지 않는다.
2. 모델·normalizer·주입기를 고정한 채 **장비와 시간 블록을 재표집**한다. 먼저 AGV/OHT 각각에서
   원 장비 수만큼 복원 추출하고, 뽑힌 장비의 각 연속 정상 구간에서 점수 블록을 원 길이까지 복원 추출한다.
   primary는 연속 창 시작점 **12개**(stride 10에서 첫–끝 시작점 차이 110 tick, raw 지원 140 tick), 민감도는 6/30개다.
   구간 안에서만 circular block을 사용하고, raw 입력을 이어 붙이거나 합성을 다시 생성하지 않는다.
   짧은 구간은 전체를 하나의 블록으로 두고 `low_resolution`으로 기록한다. 원 구간을 넘겨
   세션·결측·이상 구간을 연결하지 않는다. 구간 내 정상성 가정과 circular 경계의 한계도 기록한다.
3. 정상 base 하나가 뽑힐 때 **그 base의 합성 파생본 전체**를 함께 뽑는다. 모델·정책 간에도 같은
   재표집 ID를 공유한다. seed=20260929, 2,000회, 장비/합성 가중치를 각 반복에 다시 정규화하여
   NQ/SYN 임계값을 재계산하고 2.5/97.5 분위수 구간을 낸다. 9개 합성을 독립 표본으로 세지 않는다.
4. cal 장비를 하나씩 뺀 임계값 범위와, cal만 stride 30으로 선택한 **offset 0/10/20 tick** 결과를
   모두 보조표에 낸다. 각 offset은 원 세션 시작 기준이며 기존 stride-10 base/bank의 부분집합이다.
   주 프로토콜의 stride 10이나 임계값을 유리한 CI·offset 결과로 교체하지 않는다.

이는 **고정 모델·관측된 cal 장비/구간에 조건부인 기술적 민감도 분석**이다. 장비가 네 대뿐이므로
95% 구간이 현장 99% 정상 coverage를 보장하지 않는다. 동일·퇴화 임계값 비율과 짧은 구간 비율,
블록 길이별 결과, bootstrap 계산 시간도 공개한다. §8.3의 held-out 성능 CI와 별도 표로 보관한다.

## 8. 실제 평가·합성 평가·보정 격차를 구분한다

### 8.1 표를 세 개로 분리한다

1. **실제 라벨 평가표:** 모달리티/탐지기/팔/threshold별 Mild·Moderate·Severe recall, pure-Normal FPR,
   장비별·AGV/OHT별 값, TP/FN/FP/TN 분모. binary score를 4-class 분류기 F1과 직접 비교하지 않는다.
2. **합성 평가표:** 동결 주입기를 held-out의 pure-Normal raw 사본에 적용한다. fit 통계·주입기·threshold는 그대로 둔다.
   이 held-out Normal은 **평가 입력일 뿐** fitting/적응에 쓰지 않는다. cal 합성을 재평가해서 탐지율을 보고하지 않는다.
3. **격차표:** 위 두 표를 ID로 연결해 차이와 CI만 보고한다. 독자가 합성 수치를 실측 탐지율로 오해하지 않게 평가 종류를 제목에 쓴다.

### 8.2 보정 격차의 계산

장비 `d`, 실제 class `k`, 고정 threshold에서:

```text
gap[d,k] = TPR_syn[d, 사전 고정 family×강도 혼합] − Recall_real[d,k]
gap > 0 : 합성으로 예상한 검출률이 실제보다 높다 (낙관)
gap < 0 : 합성으로 예상한 검출률이 실제보다 낮다
```

강도 L/M/H는 실제 severity와 동등하다는 근거가 없다. 따라서 강도를 class에 맞춰 붙이지 않고
`TPR_syn[strength] − Recall_real[class]`의 3×3 보조표도 제시한다. 이 차이는 확률 calibration error가 아니라
**명시된 두 사건 분포 간 탐지율 격차**다. family 혼합비에 의존하므로 하나의 숫자로 보편화하지 않는다.
해당 장비에 pure-Normal 또는 class k가 없으면 gap/recall은 NA이며 공통 적격 장비 수를 표시한다.

실제 점수의 평균이 Normal < Mild < Moderate < Severe인지 장비별로 확인하고 중앙값·분포 겹침도 보고한다.
원문 6/8 기준은 4개 class가 모두 존재하는 장비를 분모로 할 때만 평가한다. 적격 장비가 8대 미만이면
`6/8 통과`라고 표기하지 않는다. 합성 강도의 단조성은 다른 표에 둔다.

### 8.3 불확실성과 해석

주 요약은 장비 macro-average, pooled window 값은 보조다. 동일 장비·fold·seed·event manifest로 모델 차이를 짝짓는다.
seed 3개를 먼저 장비 안에서 평균하고, 장비를 AGV/OHT별로 재표집하는 paired cluster bootstrap 10,000회로
기술적 95% CI를 산출한다. 각 재표집에서 모든 비교군의 같은 장비를 함께 뽑고 seed 변동은 별도로 보고한다.
32대의 out-of-fold 모델들은 학습 데이터를 공유하므로 이 CI는 고정 학습 절차의 관측 장비 변동을 요약하며,
독립 재학습 전체의 불확실성이나 신규 현장 coverage를 보장하지 않는다. 4개 fold별 효과도 함께 제시한다.
많은 조건 중 유리한 비교를 고르지 않도록 F−S, F−T, BIN−AE, SYN−NQ, oracle−blind를 사전에 고정한다.

이 단계는 **window 검출 실험**이다. window recall을 사건 recall로 부르지 않으며, 시간당 오경보·선행시간은 계산하지 않는다.
이 지표에는 연속 관측시간, 실제 event onset, alarm merge/refractory 정책이 별도로 필요하다.
point adjustment로 사건 전체를 맞춘 것으로 바꾸지 않는다([Kim et al.](https://arxiv.org/abs/2109.05257)).

### 8.4 동결 후 합성 강도의 해석표

`[1,2,4]*fit-Normal std`는 유지한다. **모델·주입기·임계값·평가 규칙을 모두 동결한 뒤에만**
실제 class 분포와 합성 강도 분포를 나란히 보고한다. 비교 표를 blind 적합·모델 선택·임계값 재조정에
되먹이지 않는다. 후속 grid 변경이 필요하면 새 탐색 실험으로 분리한다.

| 보고 항목 | 비교 계약 |
|---|---|
| 주입 크기 | 장비·채널·family·강도별 fit-Normal scale, nominal/realized Δ를 °C/A/µg/m³로 기록 |
| 주입 후 절대 수준 | raw 창의 mean/std(ddof=0)/max를 실제 pure-class 창과 **같은 연산**으로 계산; 열화상은 같은 30×120×160 공간·시간 범위 |
| 분포 겹침 | 위 요약통계의 장비별 5/50/95 분위수와 분모를 실제 class·합성 family/강도·QC 층별로 보고 |
| 실제 class−Normal 차이 | 같은 held-out 장비에서 관측된 요약통계 분포의 차이. 실제 event onset 변화량이나 인과 효과로 부르지 않음 |
| 점수 포화·바닥 | family/강도별 합성 TPR이 0/1인 경우에도 TP/전체 수, score 분포와 동결 threshold를 함께 보고 |

주입 **Δ**와 실제 class의 **절대 평균**을 직접 비교하지 않는다. base+Δ와 class의 절대 수준,
또는 서로 대응하는 차이 요약끼리 비교한다. Normal/class가 없는 장비는 NA로 두고 대체값을 만들지 않는다.
검토의 CT1 예시 숫자만 계산해도 `2.16 + 19.87 = 22.03 A < 32.95 A`이므로
“+1σ가 이미 Severe 평균을 넘는다”는 설명은 성립하지 않는다. 그 과거 수치를 fit-Normal 통계로 사용하지 않는다.

**검토 중 실제 통계 노출 기록:** Claude는 갱신 (3)에서 위 계산을 철회하고, 19.87 A가
Normal-only가 아닌 전 class 표준편차였다고 정정했다. 이어 32대 전체의 8,000 tick 표본에서
Normal-only 통계를 다시 계산했다고 보고했다. 이는 fold별 fit 16대의 pure-Normal 고유 raw tick
통계가 아니다. 처음에는 인용한 파일이 로컬에 없었으나, 갱신 (5)에서 검토자가 생성 호스트를

사전 독립적인 blind 선택이라고 소급해서 부르지 않는다. 사양·정격 출처를 갖춘 물리 격자는

합성과 실제 분포가 겹치지 않더라도 gap은 **그 두 명시된 분포의 탐지율 차이**로 정의된다.
다만 다른 강도·장비·현장 분포에 대한 대표성은 제한된다. 이 표는 그런 한계를 드러내는 사후 진단이며,
합성 L/M/H를 실제 Mild/Moderate/Severe에 대응시키거나 새로운 수용 기준을 만드는 절차가 아니다.

## 9. 실행 규모와 단계별 중단 조건

| 단계 | 범위 | 새 학습 수 | 목적 |
|---|---|---:|---|
| P0 | 데이터 manifest·라벨 접근·주입·shape·QC 검증 + 4종 통계 기준 모델 구성 | 0 (별도 구성 16건: fit 통계 12 + dev ECDF 4) | 누수/단위/재현성 차단, 기준 모델 포함 실제 이상 성능은 열지 않음 |
| P1a | CT1 공통 split, fold0, seed42, blind의 **T-AE 30 epoch 1회** | 1 (P1에 포함) | decoder 포함 시간·메모리·I/O 실측; held-out 실제 점수 비공개 |
| P1b | 같은 조건의 S-AE/F-AE/S-BIN/T-BIN/F-BIN | +5 (P1 총 6) | 나머지 구조별 비용·학습 안정성·cal 불확실성 경로 점검 |
| P2 | blind, 4fold×seed42 전체 | 총 24 (P1 재사용 시 +18) | 프로토콜 동결 후 첫 장비 비교 |
| P3 | blind, 4fold×3seed 전체 | 총 72 (P2 이후 +48) | seed·장비 변동 분리 |
| P4 | oracle BIN, 3모달리티×4fold×3seed | +36 | AE는 재학습하지 않고 oracle 합성 보정/평가만 추가 |
| 확장 | CT2의 S/F, 양팔, 4fold×3seed | +72 | 24 AE + 48 BIN. T 재사용. 주 비교와 분리 |

기본 전체는 **조건부 계획상 학습 108회**(AE 36 + blind BIN 36 + oracle BIN 36), nominal 평가 조건은
`3모달리티×2탐지기×2팔×4fold×3seed×2threshold = 288`개다. AE-NQ의 팔 중복은 독립 실험으로 세지 않는다.
L과 통계 기준 모델·cal 불확실성의 추가 평가 비용은 288개에 포함하지 않으며 별도 회계한다.
CT2까지 포함하면 학습 180회이며 최초 실행 범위는 P0/P1이 적절하다.

**P1a를 끝까지 실측한 뒤 P1b, 전체 P1의 비용 검토 뒤 P2~P4 확대 여부를 정한다.**
열화상 decoder는 창당 `30*120*160 = 576,000`개 값을 출력하므로 encoder 분류기 비용을 그대로 쓸 수 없다.
epoch별 시간·전체 시간·peak GPU memory·encoder/decoder 파라미터 수·I/O 시간·effective batch·동시 GPU 수를
저장한다. F-AE가 T-AE보다 클 수 있으므로 T-AE 한 번의 시간만으로 108회를 모두 추정하지 않는다.
6개 구조별 실측으로 총 GPU-hours와 병렬 wall-clock 예산을 구분하고 oracle BIN은 실측 전 추정임을 표시한다.
cal/bootstrap 시간도 별도 더한다. 기존 V2+ 23분/run이나 검토 의견의 13~18시간은 새 모델의 실측 예산이 아니다.
`estimated_wall_clock_hours`는 현재 null을 유지한다. OOM·비정상 loss·원본 손상·범위 밖 정보 유입이면
실패를 기록하고 해당 단계에서 멈춘다. 모델·batch·정밀도를 바꾸면 프로토콜을 갱신한다.

P1 뒤 변경이 생기면 P1 산출물을 본 실험에 재사용하지 않는다. P2의 실제 결과를 본 뒤 설계를 바꾸면 후속 실험을 탐색적으로 표기한다.
4fold 전체 프로토콜을 동결한 뒤 평가를 일괄 공개하며, fold0 결과를 보고 나머지 fold 설정을 고치지 않는다.

**완료 gate:** pure-normal 필터, 장비/세션/base ID 분리, 분할 전후 accounting, 생성 재현성,
normalizer fit provenance, score 방향, threshold 재현성, dropped-modality 불변성 검사를 통과할 것.
실제 이상 학습 가중치/통계 유입, fit↔heldout 중복, 무효 물리값, NaN/OOM, budget 불일치가 발생하면 해당 비교를 완료로 표시하지 않는다.

원문의 Severe recall 0.9는 **오프라인 관심 기준**으로 함께 확인한다. 다만 “작은 양수 gap”과 “oracle에 크게 뒤지지 않음”의
허용 폭은 아직 없다. 임의의 숫자를 ACTIVE 수용 기준으로 만들지 않는다. 점추정과 CI를 먼저 제시하고,
현장 배포 여부는 O-104/O-105·새로운 현장 증거로 판단한다. 작은 gap만으로 배포 승인을 내리지 않는다.

### 13.8 P1b 실행 전 제안 검토 — BIN 노출량과 필수 라벨 충돌

P1a 실행 중 Claude의 검토 (20)을 읽고, 아직 명시되지 않은 BIN epoch 길이·합성 순회·dev 집계를
검토했다. 아래는 **실행 전 제안과 진단**이며 P1b 실행 승인이나 전체 protocol freeze가 아니다.
현재 모델 코드와 실행 중인 P1a 패킷은 변경하지 않는다.

fold0 fit Normal은 2,088창, accepted 합성은 16,682건이고 dev는 525창/4,183건이다.
fit Normal 한 순회마다 같은 수의 합성을 노출하고, 합성은 seed별 순열을 epoch 경계에 이어
소비하는 안(A')은 30 epoch에서 학습 노출 125,280창이다. dev의 전체 Normal/합성을 매 epoch
검사하면 추가 141,240창, 합계 **266,520창**이다. P1a의 train+dev 합계 78,390창과 같은 분모로
비교한 노출량 비는 **3.399923배**다. 합성 전수 순회마다 Normal을 반복하는 안(B)은 dev 포함
1,142,160창, **14.570226배**다. BIN은 decoder가 없으므로 이 비를 연산 시간 비로 쓰지 않는다.

A'의 합성 양성 노출 62,640건은 전체 순열 3회와 추가 12,594건이다. 사건별 3회/4회 노출의 차이는
최대 1회지만, 어느 사건이 한 번 더 등장하는지는 seed에 따라 달라진다. 복원추출 안의 미노출 사건
390.34건은 기대값이다. 무복원 순회가 모든 seed 표집 변동을 없앤다는 해석은 하지 않는다.
Normal 8+합성 8의 배치를 쓰면 fold0 fit에서는 261개 온전한 배치가 생긴다. 다른 크기에서도 마지막
배치는 1:1을 유지하고 실제 크기로 나누는 규약이 필요하다. 문자열 namespace는 `SeedSequence`에
직접 전달하지 않고 기존 해시 기반 seed 규약으로 명시해야 한다.

S-BIN에서 thermal-only, T-BIN에서 sensor-only 사건은 해당 base의 원시 모달리티 값을 바꾸지 않는다.
정규화와 최종 tensor까지 동일하고, 고정된 결정적 분류기가 같은 입력에 같은 확률을 내는 조건에서,
Normal 가중치 `a_i`와 같은 base의
불가시 positive 가중치 합 `b_i`가 만드는 **필수 충돌 BCE 하한**은 다음과 같다(자연로그, `0 log 0=0`).

`Σ_i [(a_i+b_i) log(a_i+b_i) − a_i log(a_i) − b_i log(b_i)]`

이는 가시 양성의 완전 분리를 허용하고 다른 base 사이의 추가 입력 충돌을 무시한 낙관적 하한이다.
모델이 실제로 달성할 dev loss, 학습 성공 기준, 현장 성능을 예측하지 않는다. 전체 불가시 비율만
넣는 식은 base별 비율이 다를 때 이 하한을 계산하지 못한다. 선택적 거부가 있는 T에서 차이가 크다.

| 모집단·가중 시나리오(정상/합성 각각 1/2) | S 필수 충돌 BCE 하한 | T 필수 충돌 BCE 하한 |
|---|---:|---:|
| fit 클래스 내부 창/사건 균등 | 0.403164 | 0.300870 |
| dev 클래스 내부 창/사건 균등 | 0.403831 | 0.298856 |
| dev 클래스 내부 장비 균등 제안 | 0.403376 | 0.300238 |

F의 이 계산상 하한 0은 추가 충돌을 조사한 결과나 100% 분리 가능성을 증명한 값이 아니다.
원시 데이터·모델 예측·held-out을 읽지 않고 동결 사건 JSONL의 accepted/changed/role/base/device로
계산했다. source JSONL SHA는 `3d8991a979f9235be9cc99d9d010493b7720e7d57549849b57f45b8b876ffa62`,
진단 payload SHA는 `4166c67cb9a18a1ef9589524b17276b85deaad054d872cffc48c8da98c86b44b`다.
파일은 `/home/keti/agent-collaboration/factory-safety/p1b-forced-label-conflict-diagnostic.json`에 있다.

dev의 전체 class-balanced BCE와 장비 균등 선택 규약은 구분하여 검토한다. 장비 균등 dev와
균등 accepted stream 학습은 동일한 목적함수가 아니다. threshold의 장비×family×strength 가중을
학습/선택에 자동으로 복사하지 않으며, 현재 보정 결과를 보고 학습 가중을 고르지 않는다.

합성 전체 열화상 float32 캐시는 48,072,960,000 bytes다. 정규화된 Normal에 수식상 delta를 더하는
shortcut은 float32 반올림 및 RNG·물리 제약 검사 재현을 따로 검증해야 하므로 채택하지 않았다.
우선 canonical reader의 Normal 배열 dtype/shape/bytes와 sensor/label/hash를 그대로 보존하고
기존 `inject_blind`의 raw→주입→normalizer 순서를 재사용하는 안을 검토한다. float64 열화상이면
payload 12,040,704,000 bytes, float32면 6,020,352,000 bytes다. 원본 dtype 전수 확인 전 고정하지 않는다.
주입 함수 내부의 float64 변환과 Normal 정규화의 자료형 규칙은 별개다. Normal의 float32 배열을
캐시에서 임의로 float64로 승격하면 다시 float32로 내리더라도 반올림 결과가 달라질 수 있다.
인공 배열의 NumPy 1.26.4 확인에서는 최대 차이 `9.54e-7`을 보았으며, 서버 NumPy 2.2.6의 실제 원본
검증을 대신하지 않는다. 위 충돌 하한도 모델 입력 동일성 가정을 포함한 metadata 진단이다.
캐시는 파일 재읽기와 디코딩을 줄이는 방안이며, Normal·합성의 최종 tensor까지 canonical reader와
비트 동일성을 검증하고 비용을 측정하기 전에 구현 완료로 표시하지 않는다.
