## 0. 이 문서의 위치

외부 검토 문서는 `multi_sensor_anomaly_detection-feature-jetson-sensor-integration.zip`
스냅샷만 받아 작성됐다. 그 ZIP에는 **모델 가중치, 실험 결과 JSON, AI Hub 원시 자료,
공급자 공식 모델이 없었다.** 검토 문서는 이 한계를 스스로 명시했다.

이 문서는 **같은 주장들을 실제 장비에서 실측 검증한 결과**와, 그 결과에 따른 실행 계획이다.
원본 검토 문서는 아카이브 SHA-256이 명시된 외부 산출물이므로 수정하지 않는다.

검토자가 ZIP에 raw·가중치가 없어 재현하지 않았다는 사실은 **검토 범위의 설명**이며, 현장 장비에
자료가 없다는 뜻이 아니다(업무 지침 §16 범위 정정). 이 장비에는 raw 5 trial·processed·
`results.json` 16개·checkpoint·ONNX/TRT가 있고, AI Hub extracted만 비어 있다(§6).

근거 수준 표기는 원본과 동일하게 유지한다.

- **실측 확정:** 이 장비의 실제 코드·데이터·산출물에서 직접 측정.
- **국소 검증:** 순수 함수·합성 반례·수식 구조 확인. 학습 실행이 아님.
- **판단 보류:** 근거가 없어 결정하지 않음.

이번 검증에서 하지 않은 것: 모델 학습, 추론 실행, 코드 수정, raw/processed 데이터 변경.
이 장비에는 torch가 없어 학습·추론은 애초에 불가능하다.

### 1.3 F08 — 닫힌 항목

세션 내 인접 delta   111,528쌍 전부 정확히 1 s    (delta != 1 이 0건, 중복 timestamp 0건)
세션 경계 gap        전부 >= 173 s               (1~120 s 구간이 존재하지 않음)

파일명 timestamp와 JSON `meta_info.collection_time`을 45,618건 대조해 100% 일치를 확인했고,

코드 결함은 실재하지만 발현되지 않았다. **향후 데이터 대비 assertion 추가 권고만 유효**하며

## 3. P0 — 논문 제출 전 필수 수정

재실험 없이 문서만으로 가능하며, 신뢰도 영향이 가장 크다.

### 3.1 공식 baseline의 정체 (최우선)

`data/aihub/models/AI모델/2.AI학습모델파일/best_model.pth`를 torch 없이 ZIP·pickle로 열어
state_dict 형상을 복원했다.

```
sensor_encoder.lstm.weight_ih_l0   (512, 8)      -> LSTM(8, 128, 3층) 단방향
sensor_encoder.fc                  (128, 128)
thermal_encoder.conv_layers.0/3/6  1->16->32->64  -> 120x160, MaxPool 3회
thermal_encoder.fc                 (128, 19200)
fc                                 (4, 256)       -> concat 후 Linear
총 2,833,412 params
attention / patch-embedding / normalization 텐서 0개
```

**공식 모델은 Multimodal LSTM+CNN이다.** readme의 "MMTransformer",
`pip install mmtransformer`, PDF의 `github.com/decisionforce/mmTransformer`는
**무관한 CVPR-2021 차량 궤적 예측 모델**을 가리키는 보일러플레이트다.
공식 `README.md:1` 제목 자체가 "열화상 및 센서 데이터 분류 모델 (Multimodal LSTM 기반)"이다.

그리고 우리 `results/baseline/results.json`의 `model_params`가 **2,833,412로 정확히 일치**한다.
`src/models/multimodal_lstm.py` 최상단은 "adapted from AI Hub code"다.
**우리 V1이 공급자 공식 아키텍처를 우리 프로토콜로 재학습한 것이다.**

수정 대상:

| 위치 | 현재 | 수정 |

| `paper_draft.md:350` | Table 6 "AI Hub reference MMTransformer [32] 0.9109 / 91.92%" | 행 삭제, 또는 "공급자 활용 가이드라인 보고치 · 아키텍처/프로토콜 미공개 · 직접 비교 불가"로 재표기 |

### 3.2 공식 프로토콜은 우리와 호환되지 않는다

공식 `data_combine.py`(배포)와 docker에서 복구한 `/app/data_preprocess.py` 기준.

| 항목 | 공식 | 우리 |
|---|---|---|
| window / stride | 30 / **1** | 30 / 10 |
| per-window label | **first timestep** | plurality vote |
| session 분할 | 없음. 폴더 내 파일명 정렬만 | 120 s gap 분할 |
| split | **stride-1 window를 랜덤 80/10/10** (`random_state=42`) | 공급자 Training/Validation 디렉터리 (장비 분리) |
| 센서 채널 순서 | `[NTC, PM10, PM2.5, PM1.0, CT1..4]` | `[NTC, PM1.0, PM2.5, PM10, CT1..4]` |
| 센서 정규화 | **없음** (raw) | train 통계 z-score |
| thermal 정규화 | **없음** (raw °C) | global min-max |
| sampler / class weight | 없음 | WeightedRandomSampler + weighted CE |
| F1 averaging | **확정 불가** (`train_manager.py` 0바이트) | macro |
| 데이터셋 | 사전 배포본 40 폴더 | 공개 111,870 subset |

공식 프로토콜은 **stride 1 window를 랜덤 분할**하므로 train/test가 29/30 겹친다.
우리 장비 분리 split이 방법론적으로 우월하며, 이 점은 주장 근거로 쓸 수 있다.

부수 주의: 공식 체크포인트는 PM1.0과 PM10이 **뒤바뀐** 순서를 기대한다.
우리 채널 순서는 배포 CSV 헤더(`NTC,PM1.0,PM2.5,PM10,CT1,CT2,CT3,CT4`)와 일치함을 확인했으므로
`src/`로 학습한 것은 문제없다. **공식 가중치를 우리 loader로 평가할 때만** 열 1과 3을 교환해야 한다.

### 3.3 "individually ineffective but synergistic" — 주장은 유지, 예산 교란만 정정

**2026-09-07 자기 정정.** 이 절의 초판은 ablation 기준선을 V1(0.9235)로 잡아 "결합 이득이 단독
합계보다 작다(sub-additive)"고 썼다. **틀렸다.** `paper_draft.md:390` Table 8의 기준선은
**V2(single-lag, `results/ablation_v2`, `name: "LSTM+TemporalDiff"`, F1 0.943008, NM 45)**이고,
V2a/V2b/V2c는 V1이 아니라 **V2에 한 요소씩 더한 변형**이다(`:327-332`). 올바른 기준선으로
다시 계산하면 논문 Table 8은 저장된 결과와 정확히 일치한다.

| 구성 | 저장된 F1 | ΔF1 vs V2 | NM | 논문 Table 8 |
|---|---:|---:|---:|---|
| V2 (base) | 0.943008 | — | 45 | 0.9430 / — / 45 |
| V2a + multiscale | 0.943211 | +0.02 %p | 45 | 0.9432 / +0.02% / 45 |
| V2b + SE | 0.931921 | **−1.11 %p** | 53 | 0.9319 / −1.11% / 53 |
| V2c + SupCon | 0.942174 | −0.08 %p | 46 | 0.9422 / −0.08% / 46 |
| V2+ (셋 결합) | 0.955000 | **+1.20 %p** | 24 | 0.9550 / +1.20% / 24 |

따라서 **"단독으로는 무효하거나 오히려 나쁘고 결합 시 개선"이라는 서술 자체는 저장된 결과가
지지한다.** 초판의 sub-additive 주장을 철회한다.

**그러나 세 가지 결함은 그대로 남는다.**

**(a) 학습 예산이 다르고 schedule 동일성이 미검증이다 — 분해는 불가.**

**2026-09-07 2차 정정.** 초판과 1차 정정은 "동일 예산으로 맞추면 +0.700 %p이므로 epoch 기여가
+0.499 %p = 주장의 41.6 %"라고 썼다. **이 귀속은 정당하지 않다.** 근거를 확인한 결과 통제
조건이 성립하지 않는다.

관측 사실은 다음까지다.

```
V2+ (results/v2plus, 단일 실행) val_f1 경로
  best over first 20 epochs   0.950009  @ epoch 20
  best over 30 epochs         0.955000  @ epoch 27
  차이                        +0.4991 %p
  lr 감소 지점                epoch 13 (1e-3 -> 5e-4), 25 (-> 2.5e-4), 29 (-> 1.25e-4)
```

**분해가 불가능한 이유 네 가지.**

1. **plateau 기반 LR schedule.** 보고값 0.955000은 **epoch 25의 LR 감소 직후 epoch 27**에서
   나왔다. scheduler가 검증 지표 정체에 반응하므로 발동 시점은 예산이 아니라 학습 경로에
   달려 있다. 30 epoch 실행을 20에서 자르는 것은 **20 epoch 예산으로 실행한 것과 다르다.**
2. **schedule 동일성 미검증.** `results/ablation_v2`의 `history`에는 `lr` 시계열이 없고
   `hparams`도 `{batch_size, lr, epochs}`만 기록한다. 두 실행이 같은 scheduler를 썼는지
   **확인할 근거가 없다.**
3. **V2 자신도 예산 한계에 있었다.** V2의 best는 20 epoch 중 **epoch 19**이고 최종 epoch는
   0.932263으로 하락했다. V2를 더 길게 돌리면 어디까지 오르는지 알 수 없으므로, 예산 차이가
   어느 방향으로 얼마나 작용하는지 정할 수 없다.
4. **초기화 미통제 + V2 반복 없음.** F03으로 두 실행의 초기 가중치가 통제되지 않았고 V2는
   단일 실행이라 분산 추정이 없다. 참고로 V2+ 3-seed F1 범위는 0.001024이고 위 epoch 구간
   차이는 0.004991로 약 5배지만, 이는 V2+ 내부 비교일 뿐 V2 arm의 분산을 대신하지 못한다.

**따라서 말할 수 있는 것은 하나다.** V2(20 epoch)와 V2+(30 epoch) 비교는 **예산이 다르고
schedule 동일성이 검증되지 않은 교란된 비교**다. 그러므로 +1.20 %p를 세 요소의 효과로
귀속할 수도, 예산 효과로 분해할 수도 없다. 교란의 방향과 크기는 **미결**이다.

이를 가려내려면 전 조건을 동일 예산·동일 scheduler·동일 초기화 통제·다중 seed로 재실행해야
한다(`EXP-20260907-003`). 재실행 전에는 어느 쪽 수치도 새로 주장하지 않는다.

**(b) 2요소 조합 3개가 없다.** one-at-a-time 3개 + all-three 1개로는 interaction을 추정할 수
없다. 2³ 설계가 필요하다(`EXP-20260907-003`).

**(c) synergy를 단일 seed로 판정했다.** V2+ F1은 3-seed(0.9557 ± 0.0006)인데 Table 8의
+1.20 %p와 NM 24는 **seed 42 단일 실행**이다. 3-seed 평균 F1 0.955659로 계산하면 +1.265 %p이고,
NM은 24/29/33으로 흩어진다(§3.4).

**조치:** "individually ineffective but synergistic" 서술은 유지한다. 단 (i) ablation과 V2+의
epoch 예산이 다르다는 사실과 동일 예산 수치(+0.70 %p)를 함께 밝히고, (ii) interaction이라는
표현은 2³ 재실행(`EXP-20260907-003`) 후에만 쓰고, (iii) Table 8의 값이 단일 seed임을 표기한다.

### 3.4 H2 판정 — 비교 기준은 정당, seed 선택과 요소 귀속이 문제

**2026-09-07 자기 정정.** 초판은 "45는 baseline이 아니라 v2a"라고 썼다. **틀렸다.**
`paper_draft.md:511`의 H2 예측은 "vs. **single-lag baseline**"이고 45는
**V2(single-lag, `results/ablation_v2`)**의 NM이다. 비교 기준 자체는 논문이 명시한 대로 정당하다.
초판의 "abstract가 baseline이라 쓰는데 실제로는 v2a" 지적을 철회한다.

**남는 결함 셋.**

**(a) 3-seed F1과 1-seed NM을 섞었다.** Table 8·Table 15의 NM 24는 **seed 42 단일 실행**인데,
같은 행의 F1은 3-seed `0.9557 ± 0.0006`이다. V2+의 NM은 seed별로 흩어진다.

```
V2+ NM   seed42=24   seed123=29   seed456=33    mean 28.67  std 3.68
V2 기준 45 대비
  best seed  24  ->  46.7 %   PASS
  3-seed 평균 28.67 -> 36.3 %  FAIL   <- 사전등록 40 % 임계 미달
  worst seed 33  ->  26.7 %   FAIL
```

즉 **H2의 "Supported" 판정은 세 실행 중 최선값 선택에 의존한다.** F1과 동일하게 3-seed로
보고하면 자체 임계치를 통과하지 못한다.

**(b) 예측은 SupCon 단독을 지목하는데 증거는 3요소 모델이다.** H2 예측문은
"SupCon (lambda = 0.1) reduces ..."인데, 근거로 든 V2 → V2+ 전이는 multiscale·SE·SupCon
셋을 동시에 바꾼다. 논문 자신의 Table 8이 **SupCon 단독(V2c) NM 46**으로 V2의 45보다 오히려
나쁘다고 적고 있다. `:513`은 H1에 대해 "combined-effect form"이라는 완화를 붙였지만
H2 판정 행에는 같은 완화가 없다.

**(c) λ 값이 실행 기록과 다르다.** H2는 `lambda = 0.1`이라 쓰지만
`results/v2plus/results.json`의 `args.supcon_weight = 0.3`이다. `temperature = 0.07`.

**(d) 임계치가 사후 삽입됐다.** `연구노트_13:50`이 "원 draft(2026-04-09 완성)는 명시적 RQ/H가
없었다", `:54`가 "RQ1-3 · H1-3 블록 삽입"이라 기록하는데, `:79`는 그 삽입된 40 %를
"사전 등록 40% 임계치 초과"라 부른다.

**조치:** (i) NM을 F1과 동일하게 3-seed로 보고하고 판정을 다시 쓴다. (ii) H2 예측문을
SupCon 단독 귀속에서 3요소 결합 효과로 고치거나, 고정 backbone에서 SupCon만 켠 비교로
근거를 교체한다(`EXP-20260907-003`). (iii) λ를 실제 실행값 0.3으로 정정한다.
(iv) "preregistered"를 post-hoc formalization으로 표기한다. **새 수치는 재실험 전 넣지 않는다.**

### 3.5 TimesNet 비교 무효

## 5. P2 — 연구 방향

검토 문서의 핵심 질문과 H-A / H-B / H-C 골격, §7 실험 설계, §7.5 평가 지표는 그대로 유지한다.
실측으로 두 가지를 확정할 수 있고, 한 가지 실험 설계가 바뀐다.

### 5.1 A안(현재 실측을 기존 8채널에 그대로 투입)은 실행 후보에서 제외된다

검토 문서 §7.4는 결정을 미뤘다. 근거가 나왔다.

```
thermal   legacy 정규화 구간 30.98 ~ 146.10 °C   (span 115.12)
          우리 FLIR valid window 23.73 ~ 38.08 °C (span 14.35)
          우리 전 범위가 입력 구간의 12.5% 만 차지, 하단은 음수 (-0.063)
          legacy 분포 중앙 88.5 °C 는 우리 관측 최고치보다 50.5 °C 높음

scalar    NTC z=-1.03   PM1.0 z=-1.36   PM2.5 z=-1.58   PM10 z=-1.56   CT1 z=-0.33
```

**CT2~4 부재와 별개로, 우리가 보유한 5채널조차 legacy 모델이 본 적 없는 구간에 있다.**
A안(legacy 8-channel 유지)은 재정규화 없이는 불가능하고, 재정규화하면 학습된 가중치의 의미가
유지되지 않는다.

→ **B안(real 5-channel)을 주 경로로 두고, A안은 부하가 걸린 CT 실측 확보 후 재검토**한다.
단 이는 §7.4의 순서(raw 재현과 물리 신호 확인 후 결정)를 대체하지 않는다.

CT1의 현재 값은 무부하 노이즈 바닥이므로(`JETSON_DATASET_PROTOCOL.md` §14) 위 z=-0.33은
"부하가 없어서"이며 legacy와의 진짜 격차는 부하 데이터 확보 후에만 알 수 있다.

**주장 범위를 좁혀 둔다** (업무 지침 §2 경계 정정).

- 배제되는 것은 **현재 실측을 기존 8채널 모델에 그대로 넣는 A안**이다.
- 정규화 불일치만으로 **미래의 모든 8채널 설계가 불가능하다고 단정하지 않는다.**
- **known-load CT1을 확보해도 CT2~4 부재는 해결되지 않는다.** 두 문제는 별개다.
- 최종 입력 설계 결정은 **G1-S 이후 handoff §11 검토**에서 한다. 이 문서가 결정하지 않는다.

### 5.2 F05가 H-A의 대조군을 바꾼다

`fc_thermal` 뒤에 활성화가 없어(`v2_plus.py:68,100`) 열화상 분기 전체가
**시간평균 CNN 특징맵의 선형 사상**으로 축약된다. 프레임 순열 잔차 1.8e-15.
즉 전체 파라미터의 **87.06%(2,481,024개)가 "창 전체 평균 외형 점수" 하나**를 만든다.

따라서 H-A의 대조군은 cross-attention이 아니라 더 작은 것부터여야 한다.

```
1. sensor-only                      368,404 params, F1 0.9513   (이미 있음)
2. + 마지막 프레임 / ROI 온도 / 핫스폿 면적    fc_thermal 없이 수십~수백 params
3. + 시간 변화 특징 (Δthermal)
4. + 경량 temporal thermal encoder
5. + 운전맥락 조건화 관계 모듈
```

2번이 현재 2,457,728 파라미터와 대등하면 §F06의 "해상도 원인" 논의 자체가 불필요해진다.
검토 문서가 "해상도 주장을 가설로 낮춘다"고 한 것보다 한 걸음 더 나아갈 수 있다.

모델이 여전히 학습할 수 있는 것도 분명히 해둔다. 센서 측은 LSTM 3층이 30 tick 전체와
lag 1/5/10 차분을 소비하므로 순서·추세·최근성이 표현된다. 열화상 측은 공간 패턴과
"시간평균 특징맵의 선형 함수"로 표현되는 통계(예: 핫스폿 평균 강도)를 학습할 수 있다.
표현할 수 없는 것은 열 상승/하강 방향, 창 내 발생 시점, 그리고 센서-열화상 선후 관계다.

### 5.3 F02 — 유효 표본은 장비 4대다

split이 이미 장비 분리인 것은 좋은 설계다. 실제 문제는 다르다.

```
train  32대 (agv01~16, oht01~16)   303 session   9,313 window
val     4대 (agv17, agv18, oht17, oht18)  39 session  1,157 window
교집합  0대
```

**독립 평가 장비가 4대뿐이고, 그 4대를 모델·lag·구성 선택에 반복 사용한 뒤 최종 성능도
같은 4대에서 보고했다.** 일반화 주장의 불확실성은 window 1,157개가 아니라 **장비 n=4**가
지배한다. window iid bootstrap은 신뢰구간을 크게 과소평가한다.

**조치:** train 32대를 장비 그룹 K-fold로 나눠 내부 validation을 만들고, val 4대는
최종 1회 보고용으로 동결한다. 불확실성은 장비 단위 bootstrap으로 계산한다.
지금까지 반복 사용한 val은 새 미사용 test가 되지 않는다.

### 5.4 F11 — FFC를 실험 설계에 반영

```
stale tick        seq 28~31 과 211~214 두 군데에만 집중
trial 내 손실     window index 0: 2/5   index 1: 4/5   index 7: 5/5
canonical 개입    tick 90~269  -> seq 211~214 와 겹친다
```

정책은 변경하지 않는다. **FFC manual 전환, post-FFC exclusion rule 추가, interpolation,
stale frame 대체 모두 금지**이며 v1 자료를 재라벨링하거나 보간하지 않는다.

**지표 표기 규칙** (업무 지침 §15/§16 지표 정정). `49/60 = 81.7 %`는 **v1 윈도 유효율**이다.
"판단 가용률"이나 "전 센서 정상 관측 시간"으로 환산하지 않는다. 실제 관측은 다음과 같이 분리해
기록한다.

```
v1 윈도 유효율        49/60 = 81.7 %      (thermal 품질 정책 기준, 학습 적격 윈도)
thermal-invalid tick  13/1800 = 0.72 %
snapshot status ok    ntc·ct1·sps30·scd30·bme680 각 1800/1800, flir 1787/1800
판단 가용률           계산 불가 - 경보를 내는 현장 모델이 없다 (§5 하단)
```

향후 승인된 별도 protocol version에서 **개입 타이밍이 다른 검증 trial과 sham control**을
설계한다. 평가에는 전체 시간 중 유효 판정 비율, 보류 시간, FFC 중 사건 누락을 포함한다.

같은 baseline의 FLIR `max_c 50.66 °C` / `min_c 15.23 °C` outlier는 해당 tick 자체는
`age < 500 ms`로 valid였고 인접 FFC stale tick 때문에 같은 window가 invalid가 되어
결과적으로 제외됐다. **새 automatic threshold로 쓰지 않는다.**
