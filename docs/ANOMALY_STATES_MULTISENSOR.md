# 멀티센서 이상상태 정의 (초안 v0.2)

작성 2026-10-12.
- v0.2 에서 A8 을 추가하고 신규 scenario `combustion` / `vapor_release` 를 매핑했다. bench 절차(§8)도 추가했다.
- **상태: 초안. 라벨링·학습에 아직 쓰지 않는다.**

## 0. 범위와 원칙

- 이 문서는 **데이터셋 수준의 상태 정의**다. 모델 class 와는 다르다. 모델로의 사상은 학습 파이프라인이 맡는다 (`JETSON_DATASET_PROTOCOL.md` §1).
- `JETSON_DATASET_PROTOCOL.md` 와 `DATA_PLATFORM_ARCHITECTURE.md` 의 다음 원칙을 그대로 따른다:
  - phase·scenario_id·severity 는 라벨이 아니다.
  - 라벨을 자동 생성하지 않는다.
  - recovery 는 기본값이 transition 이다.
  - 개입 시각과 관측 시각을 분리한다.
  - 라벨은 별도 annotation 층에 둔다.
- 단일 센서 임계값으로 정의하지 않는다. 각 상태는 다음 세 가지 근거를 함께 갖는다:
  1. **센서 조합** — 어떤 채널이 반응하고 어떤 채널이 반응하지 않아야 하는가
  2. **시간 순서와 지연** — 무엇이 먼저 반응하는가
  3. **공간** — 열화상에서 어디가 얼마나 넓게 변하는가
- 모든 판정은 **같은 설치(장비·센서 위치) 의 정상 기준선 대비**로 한다. 절대값 임계는 두지 않는다.
  - 센서 위치가 바뀌면 다른 데이터셋이다(기존 원칙).
  - 기준선 통계와 수치 기준은 현장 정상 데이터를 모은 뒤 `criteria_version` 으로 고정한다(§5). 그 전에는 수치를 쓰지 않는다.
- **안전하지 않은 상태는 만들지 않는다.** 유도 방법은 전부 컨소시엄 협의와 안전 승인 사항이다(프로토콜 §1, TBD). 이 문서의 "유도 후보"는 검토용 목록이며, 확정된 절차가 아니다.

## 2. 상태 목록

### 2.1 정상과 정상 운전 모드 (이상 아님)

`normal` 은 하나의 상태가 아니다. 운전 모드에 따라 신호가 크게 다르므로 **모드 태그**를 함께 붙인다:
`stopped` / `idle` / `running` / `high_duty` / `mode_change`.

- 모드 전환(예: 로봇 동작 시작)으로 CT 가 계단처럼 오르고 열이 천천히 따라 오르는 것은 **정상**이다.
  - A1(부하 이상)과 구별하는 근거는 운전 계획·작업 기록이다. 센서만으로는 구별할 수 없으므로 작업 기록을 annotation 근거로 받는다.

**scenario 와 상태의 관계 (2026-10-12)**
- scenario 는 "무엇을 개입했는가", 상태는 "센서에 무엇이 나타났는가" 다. 둘은 별개다.
- scenario 로 수집한 trial 안에서도 상태와 구간은 라벨링에서 사람이 정한다.

| scenario_id | 의도한 상태 | 함께 나타날 수 있는 것 |
|---|---|---|
| `combustion` | A8 (개방 화염). 그을음이나 연기가 나면 A4 의 일부 증거 | C1 사람 |
| `vapor_release` | A6 (VOC) | 증발 냉각으로 FLIR 에 국소 저온이 보일 수 있음. 분무했다면 액적이 입자로 잡힘(지양) |
| `dust` | A5 | C1 사람 |

**상태별 판단 근거와 다른 상태와 구분하는 기준:**

- **A1 부하 이상**
  - 전류가 먼저, 열은 나중이다. 열은 대략 `ΔT ∝ I²R(1−e^{−t/τ})` 를 따르고, τ 는 분~수십 분 규모다.
  - **A2 와의 구분:** CT 가 오르지 않았는데 열만 오르면 A2 다.
  - **정상 `high_duty` 와의 구분:** 운전 계획에 없는 부하 증가여야 A1 이다.
  - **전제:** CT 를 해당 부하에 물려야 한다(현재 불가).
- **A2 냉각 저하**
  - 전류가 그대로인데 장비 온도가 기준선보다 서서히 오른다.
  - 다음 경우는 **환경 원인(C2)** 이다: 주변 온도(BME680·SCD30)가 함께 오르거나, 열화상 전체가 균일하게 오른다.
- **A3 국소 과열**
  - 열화상에서 **작은 영역만** 오른다. max 와 mean 의 격차, 핫스팟 면적으로 본다.
  - 이 상태는 전체 평균 온도로는 놓친다. 그래서 **raw 프레임의 공간 정보가 필수**다.
- **A4 연소 초기 징후 (가장 위험)**
  - 다음 세 증거가 **함께** 있어야 한다:
    - 국소 고온
    - 서브마이크론 입자 증가(PM1/PM2.5 비중↑, `typical_particle_size_um` ↓)
    - VOC 증가(gas 저항↓)
  - 입자만 오르면 A5, 가스만 변하면 A6 다.
  - 문헌상 훈소 연기는 상당 부분이 0.5 µm 이하이고, 분진은 그보다 훨씬 크다. 다만 둘의 크기 분포가 겹치는 구간이 있어 입경만으로는 확정하지 않는다.
- **A5 입자상 물질 이상**
  - 굵은 입자(PM10·PM4 비중↑, `typical_particle_size_um` ↑) 위주이고, 열과 가스 변화가 없다.
  - 사람·청소 때문이면 C1·C4 다.
- **A6 공기질 변화**
  - gas 저항이 내려가거나 CO₂ 가 오르는데, 열·입자는 그대로다.
  - **가스 종류는 알 수 없다.** 생명안전 경보가 아니라 조기 징후로만 쓴다.
  - context 센서에만 근거하므로 2026 모델 입력만으로는 판단할 수 없다.
- **A8 개방 화염**
  - 열화상에 아주 작고 극단적으로 뜨거운 영역이 **갑자기** 나타난다. Lepton 측정 범위를 넘어 포화될 수 있으며, 포화 자체도 증거로 기록한다.
  - 수십 초 뒤 연소 생성물(CO₂ 소폭 상승)과 미연소 연료(gas 저항 하락)가 따라온다.
  - 깨끗한 연소라 입자는 적다. **이 점이 A4(훈소: 미세입자가 많고 열은 상대적으로 낮다)와 다르다.**
  - 사람 손(C1)이 함께 시야에 들어오므로, 라벨에는 C1 도 같이 붙는다.
- **A7 기계적 구속·마찰**
  - 정상 동작 주기의 전류 패턴(크기·모양)이 바뀌고, 관절부에 국소 열이 생긴다.
  - **전제:** CT 를 로봇 축 전원에 물리고, FLIR 시야에 관절부가 들어와야 한다. 둘 다 아직 확인되지 않았다.

### 2.3 혼동 요인 (이상 아님 — 반드시 따로 표시)

모델이 혼동 요인을 이상으로 배우지 않도록, 이상과 별도의 태그로 표시한다. 하나의 구간에 이상과 함께 붙을 수 있다.

| ID | 혼동 요인 | 전형적 서명 | 헷갈리는 상대 |
|---|---|---|---|
| C1 | 사람 진입·작업 | FLIR 에 **이동하는** 30~37 °C 영역, CO₂▲, 습도▲, 입자 소폭 | A3, A5, A6 |
| C2 | 환경 온도 변화 (냉난방·일사) | 모든 온도 채널이 **함께 천천히**, 열화상 전체가 균일 | A2 |
| C3 | 환기·문 개방 | PM·온도·습도·CO₂ 가 **동시에 빠르게** 변화 | A5, A6 |
| C4 | 청소·정비 | 분진▲ + 사람(C1) + 운전 정지 | A5 |
| C5 | 정상 운전 모드 전환 | CT 계단 변화 + 열 지연 상승, 작업 계획과 일치 | A1 |

### 2.4 데이터 품질 상태 (이상 아님 — invalid)

다음은 수집기가 이미 기록한다. 라벨링에서는 **invalid** 로 다루고 이상으로 세지 않는다:
- FLIR FFC·stale
- 센서 error·disabled
- tick 누락
- CT clipping

## 3. 심각도 (severity 0~3) 기준의 형식

수치는 정상 기준선을 모은 뒤 정한다(§5). 지금은 **어떤 축으로 잴지**만 정한다:

| 상태 | 크기 축 | 지속 축 | 확산 축 |
|---|---|---|---|
| A1 | 기준선 대비 전류 증가율 | 증가 지속 시간 | 열이 따라 오른 부위 수 |
| A2 | 기준선 대비 온도 초과량 | 상승 지속·기울기 | 고온 면적 |
| A3 | 핫스팟 max − 주변 | 지속 시간 | 핫스팟 면적 |
| A4 | 세 증거 중 동시 충족 수 | 동시 지속 시간 | — (A4 는 근거가 확인되면 최소 moderate 로 둔다 — 검토 필요) |
| A5 | PM10 기준선 대비 배수 | 지속 시간 | — |
| A6 | gas 저항 하락률, CO₂ 증가량 | 지속 시간 | — |
| A7 | 주기 패턴 변화량 | 지속 주기 수 | 관절 열 동반 여부 |

## 4. 라벨 형식 (annotation 층, 원본 불변)

trial 하나에 다음 구조의 구간 목록을 둔다. 파일 위치(예: `annotations/<annotation_version>/<device>/<unit>.json`)와 도구는 결정 후 만든다.

```json
{
  "unit": "dataset/thermal_abnormal/trial_003",
  "manifest_sha256": "…",                      // 어떤 raw 에 대한 라벨인지 고정
  "annotation_version": "anno-v1",
  "criteria_version": "multisensor-v0.1",      // 이 문서 버전
  "annotator": "…", "annotated_utc": "…",
  "intervals": [
    {"start_tick": 0, "end_tick": 89, "state": "normal", "mode": "running"},
    {"start_tick": 90, "end_tick": 141, "state": "transition"},
    {"start_tick": 142, "end_tick": 310, "state": "A3", "severity": 2,
     "onset_tick_by_modality": {"flir": 142, "ntc": 171, "ct": null, "pm": null, "gas": null},
     "evidence": ["flir_hotspot_area", "flir_max_minus_mean"],
     "confounders": [], "confidence": "high", "note": "…"},
    {"start_tick": 311, "end_tick": 359, "state": "transition"}
  ],
  "invalid_ticks": [[203, 206]]
}
```

- **모달리티별 onset tick(`onset_tick_by_modality`)이 멀티센서 정의의 핵심이다.** "무엇이 먼저 반응했는가"를 라벨에 남겨야 순서·지연 근거를 학습과 검증에 쓸 수 있다.
  - 기존 `observed_anomaly_onset_tick` 은 이 값들 중 가장 이른 값으로 정한다.
- 라벨이 가리키는 raw 는 `manifest_sha256` 으로 고정한다. raw 가 바뀌면 그 라벨은 무효다.

## 5. 수치 기준을 정하는 순서

1. 현장 설치 후 **정상 기준선**을 모은다. 운전 모드별로, 최소 며칠.
2. 채널별로 기준선 통계(분포, 일주기, 모드별 차이)를 **관측만** 한다. 보정·자동 임계는 만들지 않는다.
3. 사람이 그 통계를 보고 상태별 수치 기준(§3)을 정해 `criteria_version` 으로 고정한다. 그 뒤에만 라벨링을 시작한다.
4. 승인된 유도 trial 에서 실제 서명이 이 표와 맞는지 확인하고, 맞지 않으면 문서를 개정한다(버전 올림).

## 8. 사무실 bench 개입 절차 (2026-10-12, 사용자 결정)

- 목적: §2 의 멀티센서 서명이 실제로 그렇게 나타나는지 확인한다(가설 검증).
- 사무실 데이터는 **현장 데이터가 아니다**(프로토콜 §15). 현장 모델의 학습·평가에는 쓰지 않는다.
- 실행 형식은 모두 같다:
  ```
  ./jetson_deploy/run_python.sh jetson_deploy/scripts/12_run_trial.py \
      --scenario <combustion|vapor_release|dust> --severity <1-3> --test-mode \
      --operator-note "bench_intervention: <무엇을, 어디서, 거리, 횟수>"
  ```
- 진행: canonical 90/180/90 s 다.
  - 신호음 "ANOMALY PHASE START"(tick 90) 에 개입을 시작한다.
  - "RECOVERY PHASE START"(tick 270) 에 개입을 멈추거나 제거한다.
- **severity 는 계획한 개입 강도다. 라벨이 아니다.** 같은 scenario 안에서 일관되게 쓴다.
  - 예: 거리를 멀리 → 가까이, 양을 적게 → 많이.
  - 실제 기준은 operator_note 에 적는다.

| scenario | bench 개입 | 하는 법 | 하지 말 것 |
|---|---|---|---|
| `combustion` | 라이터 | 센서 묶음에서 **20~30 cm 이상** 떨어진 곳에서 개입 구간 동안 **5~10 초씩 여러 번** 점화한다. 횟수와 대략 시각은 operator_note 에 적는다 | 보드·케이블·플라스틱·SPS30 흡입구·BME680 바로 아래 금지. 카메라 렌즈 근접 금지. 연속 장시간 점화 금지 |
| `vapor_release` | 에탄올 증발 | 솜이나 거즈에 적셔 작은 접시에 담아 BME680 근처에 둔다. 회복 신호에 치운다 | **분무 금지**(액적이 입자로 잡히고 화재 위험) |
| `dust` | 불연성 가루 | 분필가루(탄산칼슘)·탈크를 30 cm 이상 떨어진 곳에서 살짝 털거나 뿌린다 | 밀가루·설탕·톱밥 등 **가연성 분말 금지**(분진 폭발). SPS30 흡입구에 직접 불기 금지 |

**공통 안전 규칙**
1. **`combustion` 은 `vapor_release` 나 `dust` 와 같은 날, 같은 공간에서 하지 않는다.**
   - 앞선 실험 뒤에는 충분히 환기한다.
   - BME680 gas 저항과 PM 이 기준선으로 돌아온 것을 웹 실시간 화면에서 확인한 뒤에만 점화한다.
2. 소화기를 비치하고 기관 실험실 안전 규정을 따른다.
3. trial 사이에는 이전 개입의 잔류(잔류 증기, 가라앉는 분진, 잔열)가 기준선으로 돌아올 때까지 기다린다.
   - 다음 trial 의 baseline 90 s 가 오염되지 않게 하기 위해서다.
4. 분진 실험 뒤 SPS30 측정값이 이상하면 수집을 멈추고 `13_reset_sps30.py` 로 상태를 확인한다.
   - 내부 오염이 의심되면 기록해 둔다(자동 조치 없음).
