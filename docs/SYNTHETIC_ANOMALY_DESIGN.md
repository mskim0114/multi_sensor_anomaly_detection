## 1. 왜 필요한가, 그리고 무엇을 묻는가

현장 배포는 **정상 데이터만 있는 상태에서 시작한다.** 감시 대상 장비의 이상 사건은 드물고,
유도 절차(O-104)와 수용 기준(O-105)이 아직 정해지지 않았다. 현재 Jetson 누적 240창도 전부
정상이고 라벨이 없다(N26). 그래서 "정상만으로 학습하고 합성 이상으로 임계값을 잡는" 절차가
현실적인 후보가 된다.

문제는 그 절차가 **진짜 이상을 잡는지 알 방법이 현장에는 없다**는 것이다. 합성 이상으로 평가하면
우리가 넣은 가정의 자기일관성을 재는 것이지 탐지 성능을 재는 것이 아니다.

**우리에게는 남들에게 없는 검증 수단이 있다.** AI Hub 에는 진짜 라벨이 달린 이상 데이터가 있다.
따라서 이 실험의 질문은 하나로 좁혀진다.

> **정상 데이터만으로 학습하고 합성 이상으로만 임계값을 정한 탐지기가, 한 번도 보지 않은
> 진짜 이상을 얼마나 잡는가. 그리고 합성으로 추정한 탐지율과 진짜 탐지율의 차이는 얼마인가.**

두 번째가 핵심 산출물이다. 이 **보정 격차(calibration gap)** 가 작으면 현장에서 합성 임계값을
믿을 수 있고, 크면 그 사실을 현장 가기 전에 아는 것만으로 값어치가 있다.

## 3. 실험 프로토콜

### 3.1 데이터 구성

AI Hub 학습 장비 32대를 장비 분리로 나눈다. `src/train_kfold.py:assign_folds` 를 그대로 쓴다.

```
학습셋       fold 밖 24대의 Normal 창만            <- 현장이 주는 것과 같은 모양
임계값 보정  같은 24대 Normal 창에서 만든 합성 이상  <- 진짜 이상을 한 번도 보지 않는다
평가셋       held-out 8대의 진짜 4 class 전부       <- 여기서만 진짜 이상이 등장한다
보고용       공급자 validation 4대 (선택에 불참)
```

**임계값 결정에 진짜 이상이 들어가면 실험 전체가 무효다.** 코드에서 이것이 구조적으로
불가능하도록 만든다(§7-1).

### 3.2 두 팔로 나눈다

합성 파라미터를 어디서 얻느냐로 두 조건을 만든다. 두 값의 간격이 답의 범위다.

| 팔 | 주입 파라미터 출처 | 뜻 |
|---|---|---|
| **blind** | 공학적 상식과 센서 사양만. 진짜 이상 통계를 보지 않는다 | 현장에서 실제로 가능한 조건 |
| **oracle** | 진짜 이상의 채널별 통계에 맞춰 적합 | 물리 가정이 완벽했을 때의 상한 |

blind 가 oracle 에 가까우면 물리 가정이 쉬운 문제라는 뜻이고, 멀면 합성 설계 자체가 병목이라는 뜻이다.
**oracle 은 상한 측정용이며 현장에 가져갈 수 없는 조건임을 결과에 반드시 병기한다.**

### 3.3 절차

1. 학습셋 Normal 창으로 탐지기를 학습한다(§5).
2. 학습셋 Normal 창에 주입 모델을 적용해 합성 이상을 만든다(§4).
3. 합성 이상과 학습셋 Normal 로만 임계값을 정한다. 예: 정상 오경보율 1 % 지점.
4. 그 임계값을 **고정한 채** held-out 8대의 진짜 4 class 에 적용한다.
5. 다음을 보고한다.
   - 진짜 이상 탐지율 (Mild / Moderate / Severe 별도)
   - 진짜 정상에서의 오경보율
   - **보정 격차** = (합성으로 추정한 탐지율) − (진짜 탐지율)
   - 심각도 단조성: 점수가 Normal < Mild < Moderate < Severe 순으로 커지는가

## 4. 주입 모델 명세

### 4.1 원칙

- **물리 단위에서 주입한다.** 정규화 전 raw 값(°C, A, µg/m³)에 더하고, 기존 정규화 상수로 정규화한다.
  정규화 공간에서 더하면 물리적으로 해석할 수 없는 값이 나온다.
- **물리적 하한을 깨지 않는다.** 전류·미세먼지는 음수가 될 수 없다.
- **창 경계를 넘지 않는다.** 30 tick 창 안에서 시작·진행이 끝난다. 창을 걸친 사건은 별도 유형(§4.3)이다.
- **seed 로 완전히 재현된다.** 같은 (창 id, seed, 유형, 파라미터)면 같은 결과가 나와야 한다.

### 4.2 유형

각 유형은 **시작 tick**, **지속 tick**, **크기**(해당 채널 정상 std 의 배수), **대상 채널 집합**으로
파라미터화한다. 아래 std 는 32대 8,000 tick 실측값이다.

```
NTC 9.42 °C   PM1.0 10.34   PM2.5 12.07   PM10 22.10   CT1 19.87 A   CT2 46.32   CT3 29.27   CT4 19.68
```

| 유형 | 모양 | 현장에서 대응하는 것 |
|---|---|---|
| `ramp` | 시작 tick 부터 선형 증가 | 서서히 진행되는 과열 |
| `step` | 한 tick 에서 계단 상승 후 유지 | 급작스러운 부하 변화 |
| `spike` | 짧은 돌출 후 복귀 | 간헐 접촉 불량 |
| `variance` | 평균은 유지하고 창 내 분산만 증가 | 기계적 불안정 |
| `drift` | 창 전체에 완만한 기울기 | 누적 열화 |
| `thermal_blob` | 열화상에 국소 가우시안 열점을 tick 에 따라 성장 | 국부 과열 |

**채널 결합이 중요하다.** 진짜 과열은 온도와 전류가 함께 움직인다. 단일 채널만 흔든 합성은
현실과 다르므로, 유형마다 **동반 채널과 상관**을 파라미터로 둔다. 예: `ramp(NTC) + ramp(CT, 지연 k tick)`.

열화상은 `thermal_blob` 로만 다룬다. `ThermalStats(30.98, 146.10)` 범위를 참고하되, 실측 범위가
이를 벗어난다는 점(N15: Training min −110.29 / max 172.06)을 알고 clipping 정책을 명시한다.

### 4.3 창을 걸친 사건

현장의 이상은 창 경계를 모른다. 창 단위 주입만 하면 "창 안에서 시작해 창 안에서 끝나는 사건"만
학습하게 된다. 세션 단위 시계열에 사건을 주입한 뒤 창으로 자르는 경로를 **별도 유형**으로 두고,
창 단위 주입과 결과를 나누어 보고한다.

## 5. 탐지기 후보

정상만으로 학습 가능한 것이어야 한다. 기존 V2+ 4-class 분류기는 현장에 라벨이 없으므로 그대로는 못 쓴다.

| 후보 | 비고 |
|---|---|
| 재구성 오차 | V2+ 인코더 구조를 재사용한 autoencoder. 창을 복원하고 오차를 점수로 |
| Deep SVDD 계열 | 정상 임베딩을 구에 가두고 거리로 점수 |
| 이진 분류 | 정상 vs 합성 이상. **합성 가정에 가장 강하게 의존**하므로 대조군으로 |
| 예측 오차 | 앞 k tick 으로 다음 tick 예측, 오차를 점수로 |

최소 두 개를 붙여 비교한다. 이진 분류는 **반드시 포함**한다. 합성 가정에 가장 취약한 구성이므로,
이것과 one-class 계열의 보정 격차 차이가 "합성에 얼마나 기대고 있는가"를 드러낸다.

기존 자산 재사용은 환영한다. `src/models/v2_plus.py` 의 `V2Plus.encode` 는 창을 임베딩으로 보내는
검증된 경로이고, `src/train_channel_subset.py:V2PlusChannels` 는 5채널 입력을 다루는 방법을 보여준다.

## 6. 지표와 수용 기준

### 6.1 보고할 것

```
진짜 이상 탐지율      Mild / Moderate / Severe 각각. 합쳐서 보고하지 않는다
진짜 정상 오경보율    임계값을 고정한 상태에서
보정 격차            합성 추정 탐지율 − 진짜 탐지율. 부호를 유지해 보고한다
심각도 단조성        평균 점수가 Normal < Mild < Moderate < Severe 인가
장비별 분해          held-out 8대 각각. 장비 편차가 크다는 것을 이미 안다 (N23, 장비 std 0.0145)
blind 대 oracle      두 팔의 격차
```

### 6.2 수용 기준

이 실험은 **성공/실패가 아니라 측정**이다. 다만 다음이면 이 방향을 현장에 가져갈 수 있다.

- Severe 탐지율이 진짜 이상에서 0.9 이상이고, **합성으로 추정한 값이 이를 과대평가하지 않는다**
  (보정 격차가 음수가 아니거나 작은 양수)
- 심각도 단조성이 held-out 8대 중 6대 이상에서 성립
- blind 팔이 oracle 팔의 탐지율 대비 크게 뒤지지 않는다

반대로 **보정 격차가 크게 양수면**(합성이 실제보다 잘 잡는다고 착각하게 만들면) 이 절차는
현장에서 위험하다. 그 결과도 값어치가 있으므로 그대로 보고한다.

## 7. 하지 말아야 할 것

1. **임계값 결정에 진짜 이상 라벨을 쓰지 않는다.** 코드 구조로 막는다. 임계값을 정하는 함수에
   진짜 라벨이 담긴 자료구조를 아예 넘기지 않는 형태가 좋다.
2. **합성으로 평가한 수치와 진짜로 평가한 수치를 같은 표에 섞지 않는다.** 표를 나누고 각 표의
   제목에 무엇으로 평가했는지 쓴다.
3. **합성 평가 수치를 현장 탐지율로 인용하지 않는다.** 논문·보고서 어디에도.
4. **oracle 팔의 수치를 현장 기대치로 제시하지 않는다.** 상한이며 도달 불가 조건이다.
5. `src/data/config.py` 의 `SENSOR_CHANNELS`, 정규화 상수, 기존 checkpoint, `jetson_deploy/model/*`,
   `jetson_deploy/reference/*.npz` 를 수정하지 않는다.
6. `dataset/`, `processed/` 는 커밋하지 않는다. raw 는 불변이다.
7. 합성 데이터를 `dataset/` 아래 두지 않는다. 진짜 수집 데이터와 섞이면 회복이 어렵다.
   `results/` 또는 별도 경로에 두고 생성 파라미터를 함께 남긴다.
8. commit·push 는 사용자 승인 후에만 한다 (AGENTS §6).
