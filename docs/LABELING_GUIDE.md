# 라벨링 가이드 (labeling-guide-v1)

작성 2026-10-12.
- 대상: 사무실 bench 시나리오 `combustion` / `vapor_release` / `dust` 와 `normal`.
- 도구: edge hub 웹 → [실시간] 탭의 **개입 기록**, [수신 데이터] trial 상세의 **라벨링**.
- 근거 문서: `ANOMALY_STATES_MULTISENSOR.md` (v0.2), `JETSON_DATASET_PROTOCOL.md` §1~3.

## 0. 왜 이렇게 하는가

이 데이터의 상태는 개와 고양이처럼 딱 나뉘지 않는다. 라이터를 켜면 다음과 같은 일이 생긴다.

- 열화상은 그 순간 튄다.
- CO₂ 와 gas 는 수십 초 뒤에 따라 오른다.
- 라이터를 끈 뒤에도 연소 생성물이 한동안 남는다.
- 분진은 털자마자 오르고 몇 분에 걸쳐 가라앉는다.
- 알코올 증기는 접시를 치운 뒤에도 천천히 빠진다.

그래서 **"무엇을 했는가"와 "센서에 무엇이 나타났는가"를 따로 기록**하고, 애매한 시간은 애매하다고 표시한다.

| 층 | 언제 | 누가 | 무엇 | 라벨인가 |
|---|---|---|---|---|
| 계획 구간(phase) | trial 시작 시 자동 | 러너 | baseline 0–89 / anomaly 90–269 / recovery 270–359. 신호음 | 아니다(절차) |
| **개입 기록(event)** | **실험 중 실시간** | 운영자 | [개입 시작] / [개입 종료] / 메모. 실제로 손을 쓴 순간 | 아니다(사실) |
| **상태 라벨(annotation)** | **실험 후** | 라벨 작성자 | tick 구간 + 라벨 + 확신도 + 센서별 반응 시작점 | **그렇다** |

학습용 창(window)은 상태 라벨에서 정해진 규칙으로 만든다(§5).
- 계획 구간과 개입 기록은 라벨의 **근거**로만 쓰고, 라벨을 대신하지 않는다.

## 1. 실험 중: 개입 기록 남기기

1. trial 을 시작한다(`12_run_trial.py ... --test-mode`).
2. 웹 [실시간] 탭에서 장치와 시나리오를 고른다.
3. "ANOMALY PHASE START" 신호음 뒤, 손을 쓰는 **바로 그 순간**에 기록한다.
   - 라이터: 켤 때 **[개입 시작]**, 끌 때 **[개입 종료]**. 여러 번 켜면 여러 쌍으로 기록한다.
   - 알코올: 접시를 놓을 때 [개입 시작], 치울 때 [개입 종료].
   - 분진: 털기 시작할 때 [개입 시작], 멈출 때 [개입 종료].
4. 거리·횟수·특이사항은 메모로 남긴다. 예: "30 cm", "불꽃 약함", "사람 지나감".
   - 사람이 지나가거나 창문을 연 일도 [메모만 기록]으로 남긴다. 혼동 요인(C1~C5)이기 때문이다.
5. 잘못 눌렀으면 그 줄의 [무효] 를 누른다. 기록은 지워지지 않고 무효로 표시된다.

**시각 처리**
- 개입 기록 시각은 서버 시계로 남는다.
- 서버는 heartbeat 로 측정한 Jetson 과의 시계 차이를 함께 저장하고, 이를 이용해 trial 의 tick 에 맞춘다. 화면에 tick 오차도 표시된다.
- 버튼을 누르는 사람의 반응 지연(약 1 s)은 남는다. 그래서 개입 기록도 라벨이 아니다.

## 2. 실험 후: 라벨 붙이기 (trial 상세 화면)

화면에 겹쳐 보이는 것:
- **기준선 띠**: 개입 전 baseline 구간(0–89)의 평균 ±3σ. 각 열마다 그 열의 색으로 그린다. **참고선일 뿐 임계값이 아니다.**
- **회색 음영**: 실험 중 기록한 실제 개입 구간
- **점선**: 계획상 신호음 시각
- **상단 색 막대**: 지금까지 붙인 라벨 구간

### 라벨 종류

| 라벨 | 붙이는 곳 |
|---|---|
| `normal` | 개입 전이고, 주 센서들이 기준선 띠 안에서 안정적인 구간. 회복 후 **모든 주 센서가 띠 안으로 돌아와 30 s 이상 머문 뒤**의 구간 |
| `combustion` / `vapor_release` / `dust` | 그 시나리오의 **주 센서가 기준선 띠를 분명히 벗어나 있고**, 그 원인이 이번 개입이라고 판단되는 구간(핵심 구간) |
| `transition` | 반응이 시작되는 중이거나 사그라드는 중이라 정상도 이상도 아닌 구간. **애매하면 transition** |
| `invalid` | 센서 오류·FFC·stale, 사람이 시야를 가림 등으로 판단할 수 없는 구간 |
| (라벨 없음) | 판단하지 않은 구간. 학습에서 제외된다 |

**확신도**는 각 구간의 판단이 얼마나 분명한지다(높음 / 보통 / 낮음). 학습은 기본적으로 `높음` 만 쓰고, 나머지는 평가와 분석에 쓴다.

**센서 반응 시작점**은 센서마다 "처음으로 기준선 띠를 벗어난 tick" 을 사람이 클릭해 남긴다(flir, ntc, pm, gas, co2, ct). 반응 순서와 지연을 검증하는 근거가 된다.

### 시나리오별 기준

**연소 이상 (`combustion`, 라이터)**
- 핵심 구간:
  - **불꽃이 열화상에 보이는 동안**이다. FLIR 최고온도가 기준선 띠를 크게 넘는다.
  - 여러 번 점화했다면 점화마다 핵심 구간을 따로 붙인다.
- 점화 사이와 마지막 점화 뒤:
  - CO₂ 나 gas 가 아직 띠 밖이면 `transition`(잔류 연소 생성물)이다.
  - 모두 띠 안으로 돌아오면 `normal`(30 s 규칙).
- 반응 시작점: flir(거의 즉시), co2·gas(지연).
- 손이나 사람이 열화상에 크게 잡힌 구간은 메모로 남기고, 판단이 어려우면 `invalid` 로 둔다.

**유해 증기 누출 (`vapor_release`, 에탄올)**
- 핵심 구간: **gas 저항이 기준선 띠 아래로 분명히 내려가 있는 동안**이다. 접시를 둔 동안이 대부분이다.
- 접시를 치운 뒤 gas 가 천천히 회복하는 구간은 `transition` 이다.
  - BME680 은 회복이 느리다. 띠로 돌아오기 전까지는 normal 로 붙이지 않는다.
- PM 이 함께 오르면 분무나 다른 원인이 섞인 것이다. 메모를 남기고 확신도를 낮춘다.

**분진 발생 (`dust`, 분필가루)**
- 핵심 구간: **PM10(굵은 입자)이 기준선 띠를 분명히 넘어 있는 동안**이다. 털기 시작 직후부터 최고점을 지나 크게 줄 때까지다.
- 가라앉는 꼬리(PM10 이 띠보다 높지만 계속 줄어드는 중)는 `transition` 이다.
- 열이나 gas 가 함께 변하면 사람이나 다른 개입이 섞인 것이다. 메모를 남기고 확신도를 낮춘다.

**정상 trial (`normal`)**
- 주 센서가 모두 기준선 띠 안이면 전 구간 `normal` 이다.
- 사람 진입 같은 혼동 요인이 있었던 구간은 `normal`(확신도 보통) 로 두고 메모를 남긴다. 혼동 요인 학습 데이터로 쓴다.

## 3. 판단 원칙

1. **센서를 보고 붙인다. 계획 구간이나 버튼 시각을 그대로 복사하지 않는다.** 둘은 근거일 뿐이다.
2. **애매하면 transition, 판단 불가면 invalid, 안 봤으면 비워 둔다.** 억지로 class 를 붙이지 않는다.
3. 한 구간에는 라벨 하나만 붙인다. 구간끼리 겹치지 않는다(도구가 막는다).
4. 다시 보고 고치면 저장할 때 **새 revision** 이 된다. 이전 revision 은 남는다.
   - 라벨 파일은 원본 manifest SHA 에 묶여 있다. 원본이 바뀌면 그 라벨은 무효다.
5. 혼자 라벨링하므로 일관성이 중요하다. 다음 두 가지를 권장한다:
   - 같은 날 붙인 라벨을 며칠 뒤 몇 개 골라 다시 붙여 본다. 자기 일치도를 확인하기 위해서다.
   - 기준이 바뀌면 이 가이드의 버전을 올린다.

## 4. 저장 형식

- 위치: hub `annotations/anno-v1/<device>/<unit>/rev-NNNN.json` (읽기 전용, 덮어쓰지 않음)
- 저장 항목:
  - `manifest_sha256`: 어떤 원본에 대한 라벨인지
  - `guide_version`: `labeling-guide-v1`
  - `intervals`: start_tick, end_tick, label, confidence, note
  - `onsets`: 센서별 반응 시작 tick
  - `events_snapshot`: 저장 시점의 개입 기록과 tick 매핑
  - `annotator`, `saved_utc`, `revision`
- 내보내기: `GET /api/v1/annotations/export`. 각 unit 의 최신 revision 과, 원본과 아직 일치하는지(`raw_matches`)를 준다. P2 데이터셋 빌더가 이것을 읽는다.

## 5. 학습 창으로 바꾸는 규칙 (P2 에서 구현, 지금 고정)

- 창: 30 tick(30 s), stride 는 P2 에서 정한다.
- **지속형 클래스** (`vapor_release`, `dust`, `normal`): 창 전체가 같은 라벨의 `높음` 구간 안에 있을 때만 그 라벨을 준다.
- **순간형 클래스** (`combustion`): 점화가 5~10 s 라서, 창 전체 조건으로는 샘플이 거의 남지 않는다.
  - 창 안에 `combustion`(높음) tick 이 **5 개 이상**이고, 나머지가 `transition`·`combustion` 뿐이면 `combustion` 으로 둔다.
- 창이 `invalid`, 라벨 없음, 또는 서로 다른 class 에 조금이라도 걸치면 **제외**한다.
- `transition` 만으로 된 창은 학습 class 로 쓰지 않는다. 평가에서 "애매 구간 반응"을 보는 데 쓴다.
- 분할은 **trial 단위**, 가능하면 **날짜 단위**로 한다. 같은 trial 의 창이 학습과 평가에 섞이지 않게 하기 위해서다.
