# PC4 / 센서 구간과 현장 기록의 정렬

- **상태:** `PAUSED` — 자료 확보 전 대기.
- **가설 ID:** 미부여 (보조 질문)
- **산업 문제와 필요한 의사결정:** 새 설비·새 조건에서 라벨을 만드는 비용을 줄이고, 작업자가
  경보 이후 무엇을 점검할지 판단할 근거를 제공해야 한다.
- **한 문장의 핵심 주장 (검증 상태 표시):** *가설, 미검증* — 센서 구간을 실제 운전·점검 기록과
  정렬하면 과거 사례 검색과 점검 시간이 개선된다.
- **가장 가까운 선행 연구와 차이:** SensorLM 계열은 센서–언어 정렬을 웨어러블에서 검증했다.
  제조설비 전이는 별도 검증이 필요하다. 비교표 미작성.
- **기존 방법이 실패하는 구체적 조건:** 미정의.
- **제안 방법의 최소 구성:** 통계적 기술은 수치에서 만들고, 원인·조치 설명은 **확인된 로그와
  전문가 기록**에서 얻는다. LLM이 생성한 고장명을 물리적 정답으로 되먹이지 않는다.
- **필요 데이터와 현재 확보 수준:**
  - 실제 운전 로그: **없음**
  - 점검·정비 기록: **없음**
  - 작업자 대응 텍스트: **없음**
- **필수 기준선·ablation·반례:** few-shot / transfer 비교. **미래 정보 차단**이 필수 —
  온라인 모델 입력에 사후 정비 결과가 들어가면 안 된다. 사후 정보는 label·학습 자료로만 구분한다.
- **주장별 연결된 실험 ID:** 미등록.
- **확보된 그림/표:** 없음.
- **기각·축소 조건:** 탐지 성능 개선과 설명 유용성을 별도 지표로 보고했을 때 어느 쪽도
  개선되지 않는다. 숫자·시간·채널·근거가 틀린 설명을 생성한다.
- **다른 후보와 통합 가능성:** 자료 확보 시 PC1의 보조 절로 편입 가능.
- **현재 상태와 다음 승격 조건:** `PAUSED`. 재개 조건 = 실제 운전 로그와 점검 기록에 접근 가능
  (파트너 확인 사항, `CONSORTIUM_DATA_PLATFORM_QUESTIONS.md`).
